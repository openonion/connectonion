# ConnectOnion 1.9 Paid Browser Preview Plan

Issue: [#1315](https://github.com/openonion/connectonion/issues/1315)

## Outcome

ConnectOnion 1.9 will exercise the paid Chromium 151 stack through an isolated
preview control plane before any 1.9 component can affect the production
catalogue. The preview must prove the same real $0.025 session lifecycle as 1.8,
but with exact cross-repository version and channel binding.

This work is stacked on the reviewed 1.8 candidate. It does not authorize the
1.8 merge, a ConnectOnion package publication, or promotion of preview objects
into production.

## Trust and release boundary

```text
ConnectOnion 1.9.0a1
  -> dedicated browser preview API origin
  -> signed manifest must say channel=preview
  -> exact Onionwright 0.0.13.dev2
  -> Onionwright runtime must say channel=preview
  -> preview Chromium 151 catalogue
  -> paid session create / renew / release
```

Any channel or exact-version mismatch fails before browser preparation and
before the billing boundary. `OO_API_URL` cannot redirect this preview path to
the ordinary backend; only `CONNECTONION_BROWSER_PREVIEW_API_URL` can override
the dedicated preview origin. The override requires HTTPS, except for explicit
loopback-only local testing.

## Immutable coordinates

| Component | Preview coordinate | Required evidence |
|---|---|---|
| ConnectOnion | `1.9.0a1` | wheel metadata, installed-wheel tests, channel isolation |
| Onionwright | `0.0.13.dev2`, `preview` | exact wheel checksum, installed import, 23 public exports |
| Chromium | `151.0.7922.137` | signed preview catalogue, artifact checksum and provenance |
| oo-api | isolated browser-preview service | minimal route surface, preview bucket, HTTPS, production-host guard |

The current immutable Onionwright preview wheel has SHA-256
`af2a4a617f85b58d5058e7b5e7cf11cd8175ba4f69b0f6fcd1cdfc33cc5bf729`.
The Chromium 151 bytes have SHA-256
`7de5a8f7d34e350bb6677d19d338d8f9b1b928b680211623059198d1b5793ff6`.
These values are evidence, not mutable discovery rules: the signed preview
catalogue remains authoritative at runtime.

## Execution stages

1. **Repository isolation**
   - Keep 1.8 candidate branches unchanged and reviewable.
   - Implement every 1.9 change in a dedicated worktree and stacked draft PR.
   - Record exact source commits and artifact hashes.

2. **Offline consumer contract**
   - Pin ConnectOnion to exact Onionwright preview version and channel.
   - Reject production/staging/empty signed channels before download or pip.
   - Prove system mode touches no credential, network, optional dependency, or
     billing path.
   - Prove `OO_API_URL` does not influence preview traffic.

3. **Isolated control plane**
   - Deploy only auth, licence/PAYG, artifact, and health routes on the preview
     hostname.
   - Use the preview artifact bucket and preview catalogue exclusively.
   - Reuse the production billing identity only with explicit authorization;
     do not clone or print the production environment.
   - Terminate or stop idle preview compute when the gate is paused.

4. **Local exact-artifact acceptance**
   - Build `connectonion-1.9.0a1` once from the reviewed source tree.
   - Install it with Onionwright 0.0.13.dev2 in a fresh temporary environment.
   - Run bootstrap, engine selection, async launch, renewal, close, and release
     against an isolated local preview service.

5. **Hosted preview acceptance**
   - Authenticate without printing credentials.
   - Fetch and verify a signed `channel=preview` manifest.
   - Download the exact Onionwright and Chromium objects and verify checksums.
   - Launch Chromium, exercise HTTPS, WebGL, and a browser download, verify
     server-owned egress, renew once, close, and release.
   - Reconcile exactly one $0.025 interval and verify no session remains active.

6. **Review and publication decision**
   - CI and independent review must be green on exact heads.
   - Update issue #1315 and the stacked draft PR with public-safe evidence.
   - Keep publication and merge as explicit user decisions. A successful
     preview is evidence for promotion; it is not promotion itself.

## Platform gates

Linux is the public paid-artifact acceptance platform. macOS may use the
approved internal ad-hoc enterprise build for validation. Developer ID signing,
notarization, and public macOS catalogue promotion remain future gates and must
not block internal testing or be represented as complete.

## Current gate status

- Browser and Onionwright preview objects exist immutably in the isolated
  preview bucket and their hashes have been re-downloaded and verified.
- Browser, Onionwright, and oo-api preview branches have draft PRs and passing
  local suites.
- ConnectOnion 1.9 consumer isolation is under test on this branch.
- Hosted preview deployment is paused at the shared billing/signing authority
  boundary. Copying only `NEON_DATABASE_URL`, `JWT_SECRET`, and
  `LICENSE_SIGNING_KEY` to the dedicated preview VM requires explicit approval.
- ConnectOnion merge and package publication are not authorized.
