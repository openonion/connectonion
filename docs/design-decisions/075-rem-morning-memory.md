# REM morning memory

Status: next preview candidate. The reader remains an offline, read-only snapshot.

REM is named for rapid eye movement sleep. Its daily pass gathers permitted mail
and coding sessions, updates pages, and keeps evidence. The reader should help the
owner remember and use that context after the pass. Opening on run counts made the
processing visible while leaving the remembered content below the fold.

## Interaction

1. Lead with up to three pages updated in the latest pass. Show one current line
   from each page and link to the page and its sources. Never call a current line
   a newly discovered fact: the run log says which page changed, not which claim.
2. Show one explicit cross-page Markdown link as connected context. A model's
   proposed connection is a separate review card, labelled as a question until
   the owner decides. A shared name or a similar phrase does not establish a link.
3. Ask the owner to recall an older page before revealing its already written
   context. The reveal is a reading aid, not a score or a claim that learning was
   measured. It does not write to the notebook.
4. Keep open threads in view. Put run counts and the hypnogram in a disclosure;
   keep maintenance below the library. Hide empty secondary categories in the
   navigation while keeping People, Organisations, and Projects reachable.

The night blue surface carries the changed content. The arc is a quiet reference
to the sleep cycle; the connection row conveys a real link. A bordered recall
card gives the owner a pause between seeing a cue and seeing its answer. Both
themes use local fonts, and the phone stacks the cards and thread labels.

## Limits and next steps

This preview does not synthesize a cross-page answer, persist recall progress,
or turn the reader into a live editor. `co rem open` still captures a point in
time; the timestamp and page links are explicit. A real answer interface must
return source-backed responses, and any memory correction must enter the
existing reflection/review workflow with provenance. Neither should be simulated
by a button in this static reader.

Browser evidence uses the invented notebook in `tests/fixtures/rem_reader_notebook.py`.
The owner’s private notebook is not part of the committed evidence.
