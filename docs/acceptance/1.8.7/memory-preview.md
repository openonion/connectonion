# Memory workflow preview acceptance

Tracks #1520, #1523, #1580, #1609, #1610 and #1611; follows initialization beta #1613.

Implemented surfaces: immutable attributed reflections, explicit supersession,
lossless compact views, reflection-only incremental batches, durable filtered capture,
question/link decisions, local optional whisper.cpp transcription, read-only review
page, explicit plan/extract/synthesize/render routes, persisted inquiry and method
artifacts, and maintain-first bounded one-page daily command.

Not equivalent to closing every design issue: semantic compression and its quality
evaluation, guaranteed correction entailment, provider-specific hook installation,
subscription-percent/dollar meters, scheduler promotion to daily, cross-machine
coordination, sharing permissions, and a measured multi-model factual-quality baseline
remain open. Current checks are deterministic fixtures and offline browser tests,
not claims of reliable autonomous knowledge or live local voice acceptance.

## Exercised evidence, 2026-09-20

- Full offline suite: 10,782 passed, 30 skipped on Python 3.14; subsequent source-scope replay correction passed the focused service suite.
- Final Wiki/version checks: 288 passed, 10 browser opt-ins skipped.
- Chrome acceptance: 10 passed separately; mobile/desktop review screenshots included in release assets.
- Installed wheel: 12 passed in a clean environment.
- New workflow edge cases: 19 passed, including unavailable local transcription, invalid routing, atomic proposal rejection, changed capture prefixes and accumulated failure usage.

Two live Luna runs on the same fictional Aurora project both produced structurally
accepted pages. Staged inquiry took 174.12 seconds and reported 500,515 input / 7,729
output tokens (430,848 cached input). A single-pass baseline took 70.29 seconds and
reported 244,239 input / 3,072 output tokens (207,104 cached input). These are aggregate
multi-round provider counters, not unique evidence size or generation throughput.
Costs were unavailable. There was no extraction stage for this small fixture.

Both preserved prototype/not-launched status and the team-owned delayed sample.
The staged result retained a simple product-flow diagram and more explicit evidence
limits. Manual review also found unsupported wording in the baseline: calling the
product itself offline (the fixture was offline), and placing a launch date after
review without evidence of that dependency. This small comparison does not establish
a general quality advantage. Routing remains opt-in; it costs substantially more here.

The first staged attempt failed on an overly strict source contract: a prior-page
citation was rejected even when paired with direct evidence. The accepted page stayed
unchanged. The validator now allows derived context but refuses a resolved finding
whose only citations are derived context. Failure usage is retained separately.
