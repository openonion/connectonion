## Real launchd observations

The candidate's HostService registered a temporary GUI-user job running a native
Host from a synthetic project. Matching local health was checked against the
launchd process's listening socket, not merely a shared global identity.

Observed: first healthy start; repeated start kept the same PID; SIGKILL of the
owned PID was followed by a different healthy PID; stop reported not running;
restart became healthy; uninstall removed the service definition. A separate
trial used project `.env` AGENT_PORT=18764 while YAML named 18763; readiness
followed the actual socket and succeeded. Both trials removed their jobs.

The trial found a real failure before the fix: immediate restart returned
launchctl bootstrap code 5 while its previous job was retiring. The subsequent
instrumented trial captured code 5 followed by a successful bounded retry.
No root command or other user's service was used. A first five-second readiness
attempt also failed without retained startup logs; its cause is unproven. The
candidate now gives startup a monotonic thirty-second observation window.
