# Granola Without the Lockfile

When we audited why the Granola connector was the last icon stranded under "Integrations in review" on the README while Asana, Obsidian, and Notion had already shipped, the culprit turned out to be a well-intentioned safety check placed in the wrong layer.

The earlier draft tried to prove that `co granola changes` and `co granola show` would never touch the network without user consent. To enforce that, the CLI imported REM's internal state helpers and refused to run unless `.state/subscriptions.json` already contained a nested `granola.remote.selection` record with an approved `folder_id`. Because `co rem sources` had no special-case code to write that Granola-specific JSON shape—precisely what Design Decision 081 had abolished—a fresh install hit a classic catch-22. Running `co granola changes` in a terminal told you to approve Granola in `co rem sources` first, and `co rem sources` had no way to create the file `co granola` was waiting for. A command meant to be a standalone Unix tool could not even be tested by a human at a shell prompt without hand-crafting a hidden state file.

Once you see the inversion, the fix is immediate: a `co` source command owns scope, while REM owns consent. `co granola` does not need to know REM exists. You hand it `--folder <id>` on the command line (and `--include-children` if that personal folder nests subfolders, since Granola's API includes descendants when querying a parent), and `co granola` verifies live against `/v1/folders` that the folder and every child under it belong to your personal space rather than a shared company workspace. At the HTTP boundary, private scratchpads, verbatim transcripts, and attendee emails are dropped before any caller sees the note, and `changes --json` captures `until` before the first page request so the next `--since` cursor never misses a note edited mid-flight.

Moving consent back out of the CLI shrank the connector by a third, reduced `cli/main.py` from a 133-line inline command dump to two lines, and made `co granola` work the first time on a clean machine with nothing more than `GRANOLA_API_KEY` and a folder ID.
