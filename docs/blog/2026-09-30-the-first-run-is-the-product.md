# The first run is the product

We measured the notebook's cost in tokens, pages and citations for weeks. The
owner measured it differently. On 2026-09-30 they said onboarding was not
smooth: the first time someone uses it, it should be simple, clear, and give
direct value. Then they looked at their own first run.

Ten and a half minutes. A 15,498-line log. 370 people, 138 organisations and 24
projects, every one an empty frame marked "not investigated". Twelve questions
about addresses, each with its own command. And the one command that would put
something on a page, `investigate me`, was left for the person to find.

Every part of that was defensible. The map needs no model, so it costs
nothing. Asking before merging an address is safer than guessing. Investigating
was a separate step so nobody paid for a model run they did not ask for. Added
up, a new person spent ten minutes to receive homework.

The fix was not a new feature so much as an order. The script still runs first
and still costs nothing, but it prints one line per stage, and the moment the
map is done it prints the one page that already has something in it: yours. Then
it keeps going on its own, says what it will spend, and writes your page and
the pages of the projects you touched this fortnight. The questions shrink to
one line. The next command is the same in every place it is named.

Underneath, three changes made that affordable. Project pages come from the
messages you typed to your coding agents, one call each. People come from
searching saved mail instead of summarising all of it: one person went from 31
calls and 8.2M tokens to one call and 1.93M. And the daily round works on what
is new, so a quiet day costs nothing.

The lesson: a first run is not setup before the product. It is the product,
seen first. If the first thing it produces is a list of empty pages, that is
what the product is, to everyone who does not get past it.
