# The pass that wrote nothing

An installed public a42 preview spent 11 minutes 12 seconds on a real five-day
Gmail and Outlook init. Its map completed: eleven People and two projects.
The owner and three People investigations timed out; the selected project
received a model authentication 403. No memory pages were written. Init did
install its root-specific nightly job, which we stopped after the test.

The Home page nevertheless said “Ready when there is something new.” Its
latest-pass summary treated zero updated pages as a quiet night. That same
empty state also represented a blocked first run. A reader could not tell
whether REM had checked their context or failed to create it.

Home now shows the number of failed investigations and a short, classified
reason. Raw runner output stays out of the summary. A keyboard-accessible
44px button opens the maintenance record. If other pages were written, their
cards remain visible alongside the failures. A wholly failed pass explicitly
says no memory pages were written, while the source map remains available.

This fixes visibility, not model access. A separate minimal Claude request
also returned authentication 403. Preflight and stopping queued work after
an access failure remain in [#2302](https://github.com/openonion/connectonion/issues/2302).
A full historical investigation still needs a successful real run; an
estimate or a rendered map is not evidence that the memory was written.

We prepared the reporting fix for a43 with the same failed logs in phone and
desktop before-and-after images. The package built and its isolated installed
wheel passed thirteen acceptance checks. That separation matters: a verified
artifact can still fail to write a useful memory when the account behind it
refuses the model request. Publication is a distribution gate, not proof that
the first morning is ready.
