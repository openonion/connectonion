# Closing the privacy curtain on the server

While verifying a relation-card privacy fix on a shared notebook snapshot, we opened Chrome DevTools on the rendered `file.html` and searched the raw HTML source for a sentence we had just watched vanish from the screen under Public only. It was sitting there verbatim inside the embedded JSON payload. Our privacy curtain had worked faithfully in the browser DOM, removing every `[personal]` and `[sensitive]` passage on load, yet the shared HTML still carried the unredacted markdown for every page underneath it—meaning anyone handed a shared link needed nothing more than View Source to read everything the curtain pretended to hide.

Once we pulled that thread, the same assumption showed up in two adjacent places. First, a non-default `--root` notebook rendered for a fixture script quietly inherited `~/.co/wechat/keys.json` from the user's home directory, because `subscriptions()` treated a home-wide WeChat key file as consent for every notebook on the machine rather than only the owner's `~/.co/rem`. Second, on the client side, search results and Knowledge entry headers still read raw `r.title` directly instead of passing through the masked `pageName(r)` helper that prose links and the graph already used, leaving small side doors open around the same privacy boundary.

The fix was to make privacy a serialization invariant instead of a rendering afterthought. In `reader.py`, any shared snapshot (`local=False`) now strips private pages, private cross-links, and `[personal]` or `[sensitive]` passages from markdown bodies and cached translations before the payload is ever encoded into JSON or HTML, while leaving the owner's own local reader untouched so the three-level curtain still works on their machine. At the same time, `subscriptions()` now scopes home-derived WeChat defaults strictly to `~/.co/rem` unless a secondary notebook explicitly declares WeChat in its own state file, and every remaining title surface routes through `pageName(r)`. Checking the resulting shared HTML with a literal grep for every marked secret—and seeing zero hits—drove home the simplest rule of local-first privacy: if the viewer is not allowed to see a sentence, never hand their browser the bytes in the first place.
