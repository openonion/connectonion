# A hidden field is still a promise

In a first-run REM page, one field said how the user writes to themselves. It
contained only `Unknown`. The owner template had already removed that question,
and the reader hid the empty section. On a phone, though, the page ended with a
notice that one section was still to learn. The interface made the memory feel
unfinished because the underlying page still carried an impossible question.

This was not a colour or typography problem. The writer could add a heading the
template did not require, and the page check only counted required headings.
Hiding the field in the reader left the contradiction in the document. We now
remove an empty owner-only field before saving. If the field contains a real
claim or citation, the candidate is kept for review instead of silently losing
it. The same rule applies when a nightly update touches the owner page.

A second problem was quieter. A recent decision about first-run investigation
did not use the product's name, so a topic filter selected an older rename
instead. A memory cannot infer importance from a repeated noun alone. The
bounded evidence packet now retains a recent task decision and one related
named-product message, with their original source IDs. A fresh private
five-day run put an earlier and later choice together in the first viewport.
The source text stayed on the owner's machine; the before and after screenshots
use an invented notebook.

The longer real run gave a less comfortable result. A generated citation had
no identifiable source, so REM refused to promote the page. A later five-day
run hit the same kind of failure. Refusal was the right response to an
unverifiable claim, but a first run that stops there has not delivered its
promise. That is why the owner page work remains open while a bounded citation
repair is reviewed. The design lesson is that every visible state depends on
the shape and trustworthiness of the memory beneath it, including fields the
reader chooses not to show.
