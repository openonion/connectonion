# The history was in another repository

The handoff project page knew a lot about the week it was launched: a README, a DM the owner wanted to send, a demo video. But it said almost nothing about how the feature was built. That story isn't in the handoff repository. It's in the main ConnectOnion repository, spread across a run of pull requests named "co handoff ..." and "handoff: ...". Enrich gathered two hundred GitHub search results for it, cited none, and followed the newest session instead.

Giving the model more did not help. Two hundred unordered items, most of them hits on a word somewhere in a body, are a pile to sample from, not something you can follow from start to end. So enrich now hands a project page its history as one reading guide, oldest first and month by month. It covers the pull requests and issues whose titles name the project, anywhere in the owner's organisation, and the commits that touch the project's own folder. Every month keeps its heading, with counts, even when a busy history has to show fewer examples per month. The first version cut each month to twelve lines even when the whole history was 6.5k characters, which hid most of October's handoff work. Now every line is listed while the history fits. After the change, the page cites the issue that proposed handoff and the pull requests that shipped it, encrypted it and sealed it.

Measuring the trial turned up one more problem.

A quote the page already had was sometimes lost: one or two per round. Muse puts a page back if its run loses one, but enrich had no such guard. Now both send each loss back to the writer by name. Then one person page lost a GitHub-profile sentence in enrich and again in muse, and two repairs naming its quotes did not bring it back. Both runs were refused, and the round gained nothing. Refusing the whole round for one sentence is too strict. After two repairs, the lost line now goes back where it was, with its sources renumbered, replacing the shorter copy the writer left.
