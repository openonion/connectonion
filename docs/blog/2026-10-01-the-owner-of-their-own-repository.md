# The owner of their own repository

The connectonion project page said "People and ownership: Unknown". It was
the owner's own repository, in their own folder, built in hundreds of their own
coding sessions. The same page described the project as "a command-line tool
with REM as an exploration": REM is the newest feature, and the page had been
written from the last few weeks of requests about it. Four other project pages
were written in Chinese under English headings.

None of this was the model being careless. It was following the rules. The
project-page skill said never to infer ownership from a message alone, which
is right for a colleague's repository. The project writer was handed only the
owner's typed requests, and requests show intent, not what exists. So every
line came back hedged as unverified. And the skills disagreed about language.
The project writer said English. Upkeep and extraction both said to write in
the language of the user's messages, so a Chinese session produced Chinese
notes, and those notes became Chinese pages.

Each fix is small, because each problem was one rule written for a different
case. The sessions in a project's own folders are the user's, so the user owns
that project unless the messages name someone else. The project writer is now
also given the first 3,000 characters of the project's README, citable by its
path. The README says what the project is in a paragraph, so the page no longer
has to infer that from requests. Every skill now says the same thing about
language: pages are in English, a short quote may stay as written, and names
are never translated.
