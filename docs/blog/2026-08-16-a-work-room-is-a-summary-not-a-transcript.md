# A Work Room Is a Summary, Not a Transcript

The first long Codex card had plenty of information and no hierarchy. It showed
provider detail, a text-only snapshot, approval actions, and a growing history
at the same visual level. The reader still had to hunt for the useful answer:
what is happening now, does it need a decision, and what may I safely do?

The fix is deliberately smaller than a miniature IDE. The parent conversation
has one compact semantic summary: provider, safe task category, current state,
and one entry action. The Work Room is the only detailed surface. Overview
leads with the current safe summary; Activity is its one secondary view; file
names appear only when the native adapter supplied verified evidence. There is
no default terminal transcript, second scroll region, or invented thumbnail.

This required a narrow OIP boundary. Codex and Claude Code keep their private
protocols. Their adapters emit only a finite provider lifecycle, semantic
activity, and verified approval presentation. The React reader accepts that
vocabulary and rejects arbitrary provider text. O Chat renders the normalized
state instead of parsing app-server frames or treating a raw path as UI truth.

Approval and Stop are intentionally different. A native request exposes
Core-authored what, where, and why, then offers **Allow once** and **Reject this
request**. Rejection answers that one request; it does not claim to stop an
unrelated process. Stop appears only for a starting or running provider and is
addressed to its exact invocation ID.

The acceptance evidence is not a screenshot alone. A disposable localhost Host
ran real native Codex against a C sorting task. It paused for two one-time
approvals, left source files that independently rebuilt with strict C11 flags
and passed their tests, and completed the outer Host turn. A separate run sent
an exact provider Stop and reached a `cancelled` terminal state without
cancelling the enclosing turn. Nine Chromium scenarios then checked the compact
desktop card, long activity history, approval placement, stopped state, failure
state, and 375px/320px layouts.

No visual artifact was claimed because the provider did not produce one. A real
artifact can earn a preview later through its own typed contract. Model-reviewed
Auto approval and continuation chat are likewise separate, fail-closed work;
neither is a reason to revive ACP or add a generic third adapter.

The reusable rule is simple: a Work Room should answer the next human question,
not replay every machine detail that led to it.
