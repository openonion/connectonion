# Three investigations, no pages

The maintainer initialized a Wiki from ninety days of sources, then picked three people from its map. The map was there. The model spent several minutes on each selection and produced candidate pages. When the maintainer opened the notebook afterward, none of the three had been written.

The first attempt had already exposed a simpler problem. The configured default model was refused by the account before it could investigate. Selecting another available model let the work continue, but it did not make the source path sound. Initialization had read connected mailboxes to create people entries; investigation considered their subscriptions disabled and supplied the model only a thin page and a coverage note. The model searched the mailboxes itself and found material it wanted to cite.

Then the validator rejected the pages. It recognized only source IDs from the evidence bundle it had prepared, while the model cited the messages it found through CLI commands. Some citations used listing row numbers, which can move when the mailbox listing changes; those deserve rejection. Durable message IDs are a different case. The Skill invited supplemental research, while the validator had no safe way to identify its evidence. Both parts were doing what they were told, and the person still got no page.

The run also exposed the cost of a misleading map. The map contained notice senders, bare addresses and duplicate identities. A user choosing a person from that map can spend minutes researching an identity that the map has not resolved. A fluent draft does not compensate for that ambiguity.

The retained test results identify where collection, identity resolution, model selection and citation validation disagree. We have not yet shown a repaired run through the same three cases. That is why the shipped `1.8.8b1` stays a preview, and why the Personal Wiki feature is planned for `1.9.0` with this failure blocking acceptance. The version number is less important than the next observation: can the user choose a real entry, get one evidence-backed page into the notebook, and correct it later without losing what was already right?
