# A tidy card cited the wrong claim

Two related-page cards quoted the same sentence. The reader kept the first and
filled the second with the destination page's introduction. The layout repeated
itself less. The citations still belonged to the original relationship sentence.

That is a provenance error caused by presentation, before a model is involved.
A useful sentence on another page cannot inherit evidence simply because it fits
into the same card. The existing Chinese contract test expected the replacement;
its passing result was protecting appearance rather than faithful attribution.

The proposed repair keeps every card's title, navigation and original provenance.
It hides an exactly repeated excerpt only when its origin, citations, privacy and
translation state also match. Longer statements with qualifications remain
separate. Another page's summary is not used as a replacement claim.

Keeping every duplicate was an alternative, but would retain the avoidable visual
repetition. Adding a separately sourced destination preview could be useful later;
it needs its own evidence and visual treatment. Quietly relabelling that preview
as relationship context is not an acceptable shortcut.

Seven synthetic regression cases fail before the repair; the reader/model/design
and new provenance contracts initially passed250 tests after it. Independent
review then found that removing marker-labelled text could also remove the
privacy classification of its citation row. Eight additional red cases require
the effective privacy state to survive compaction, including translated text. Those tests are pure source
and JavaScript contracts, not browser screenshots. A read-only inventory found
555 links to existing notebook pages across587 files and4 missing targets. It does
not establish that every link, page or generated claim is correct. No private
content is published, no notebook page was rewritten, and no real model or mailbox
was run. This is candidate work; phone/desktop visual acceptance remains pending.
