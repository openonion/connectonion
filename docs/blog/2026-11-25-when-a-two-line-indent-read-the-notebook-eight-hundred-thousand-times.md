# When two lines of indentation read the notebook eight hundred thousand times

When a notebook is twenty pages long, almost any design feels fast. At two thousand five hundred pages, every quiet assumption in the room starts speaking at once. Clicking the privacy toggle in the reader froze the tab for a full second. Switching between English and Chinese stalled again. Worse, when we tried to time a clean snapshot build from the terminal, three minutes passed in complete silence before our timeout killed the process.

Our first temptation was to blame the medium. Maybe a single-file HTML reader had outgrown JavaScript and needed WebAssembly, or maybe REM needed its own standalone backend service beside the Agent Host. Before building a second server, we paused to ask a simpler question: why would twenty-five hundred tiny Markdown files — barely a dozen megabytes on disk — bring a modern machine to its knees?

A four-second stack dump gave an almost embarrassing answer. Right at the top of `snapshot()`, a helper that repaired legacy privacy marks in tag titles sat two lines *above* `with held(root):`, the context manager that memoizes whole-notebook scans during a build. Outside that `with` block, every lookup of a tag's page recomputed the entire tag vocabulary from disk. With roughly three hundred and fifty tags across two thousand four hundred and sixty-seven pages, those two lines of placement turned one pass into more than eight hundred and sixty thousand file reads.

Looking closely at the boundaries exposed a second surprise, this time in security. Deep inside the local `/rem` handler sat a reassuring comment: cross-site fetches could not reach the JSON endpoints because *"a cross-site fetch would need a preflight we never grant."* Yet twenty lines above `/rem` in the Agent Host's HTTP router, a generic `OPTIONS` branch answered every path on the server with `Access-Control-Allow-Origin: *` before `/rem` was ever consulted. Meanwhile, shared snapshots hid private topic pages by title, yet still shipped `[personal]` and `[sensitive]` lines inside person and project pages in raw JSON, trusting browser CSS to hide them.

Once we saw what the code was actually doing, the urge to invent a second API disappeared. Agent Host already had the two doors an owner uses — loopback HTTP with a strict cookie on this computer, and signed WebSocket sessions through the relay when away from it. What both doors lacked was one calm Python layer over the existing `.state/rem.db` SQLite index (`store.py`) that could answer a page, a search, or a category list — including first-class `devices` beside `people` and `orgs` — while stripping private passages on the server before a shared byte ever left Python.

Moving the repair inside the build's cache scope and teaching the SQLite index to read only the Markdown files whose timestamp actually changed brought the hung three-minute snapshot down to single-digit seconds. In the browser, keying parsed page caches by language instead of wiping them on every toggle — and refusing to re-render the whole notebook when switching between `all` and `cover` — dropped the privacy switch from over a second to seventy milliseconds. We did not need a new language or a second server; we needed to stop doing the same honest work three hundred times over.
