# The audit closed every thread

We wrote a small case on purpose: eight invented mails between the user and one contact. The user promised a deck by Friday and did not send it. The contact promised an introduction next week and did not make it. The contact asked for a review the user never agreed to. The user asked about cloud credits and never heard back. A friendly introduction to someone else came last. A correct page has four open lines, each saying who asked and who agreed.

Six runs of the shipped rules produced zero to two of them. The page writer often got them right; the claim audit then failed each one as "a past request presented as a current open thread", and the last resort left `Open threads: Unknown`. The rule it applied said a past ask is not a current debt and a passed date closes a thread. Both are true of a meeting and false of a promise. The writer had a matching rule: a passed event date closes a thread, which it read as "the Friday deadline passed, so the deck thread is over."

Both rules now say the same thing. A meeting whose date has passed is history. A promise past its due date is overdue and still open. An ask nobody agreed to is "<Name> asked the user", never "<Name> owes". An ask no later message answers is open however old, until sixty days of silence make it "went quiet". Three new runs: four, two and four of four lines, and none written in the wrong direction.

Smaller changes in the same pass: an owner page's Insight is about work, never a purchase or a health note; and "it is unclear whether" and 目前无法确认是否完成 are now hedges the editing turn removes, so a page says what is known, with its date, and puts the open part in Open threads.
