# A level names the work

*2026-11-23*

The owner asked REM which model translated his pages. The answer was Sol. It was also the answer for session summaries and routine maintenance. Only tags and abstraction used Luna. Reading the table made the problem visible: we had put inexpensive transformations beside deeper writing, and the step that derives knowledge and principles sat with tags.

Those choices came from different rounds of tuning. One decision reduced effort across Sol calls; another moved the search for decisions onto Luna. Each change made sense in isolation. Together they left a table whose numbers no longer explained the work. Worse, the help still described an older table, so explaining the configuration required choosing which output to believe.

We considered changing only this notebook's model names. That would make its next translation cheaper, but a new notebook would inherit the same confusing defaults. Moving everything to Luna would be simple too, but it would treat checking a cited claim and translating a paragraph as the same kind of judgement. The owner instead chose Luna at medium effort for routine work, with Sol at low for abstraction, deeper reasoning and independent investigation.

The routing table now names that distinction directly. Level one contains tagging, translation, extraction and ordinary summaries. Level two groups narrow judgements and planning; level three covers upkeep, project pages, drafts and orchestration. All three use Luna at medium. Level four contains abstraction, muse, independent audits, synthesis and owed work. Investigation keeps its separate setting, including enrichment and page rendering; both it and level four use Sol at low. Abstract still writes decisions, knowledge and principles: changing its level changes the model, not what it is meant to preserve.

An upgrade must distinguish a shipped default from a choice. REM already records settings made through its configuration command. The migration replaces the previous routine-model defaults and effort values only when they were not explicitly chosen. An explicit model or effort stays, as does a route pinned for one stage. A legacy single-model setting needs particular care: replacing it with Luna must not accidentally drag the independent investigation group onto Luna too.

Tests exercise that boundary alongside the exact stage groups and the model and effort each stage receives. Configuration and status derive their lists from the runtime table; help and documentation have been aligned with it. This validates routing, not model quality or a measured saving. The next notebook run still needs its usual trajectory audit to establish whether Luna preserves the details in summaries and drafts, and whether Sol at low does enough independent checking.
