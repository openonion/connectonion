# The quick page missed the decision

A five-day REM first run produced an owner page in about a minute. It cited recent work, but its lead followed a different project and its open thread said the init request had no known outcome. A full pass over the same window found the more important fact: the owner had reversed an earlier direction about whether init should use a model. The two pages had access to the same source window. Their difference came from what the quick turn was handed.

The quick gather kept only the last twelve coding messages per source. Those messages were recent, but the earlier side of the decision was just outside that slice. The full turn had a separate, bounded set of dated coding excerpts chosen for temporal comparison. The quick turn did not receive it, so a short first page could confidently summarize nearby activity while missing the change that made that activity matter.

The first turn now keeps its twelve recent messages and up to six original coding turns selected as decision anchors for each source. It passes a bounded comparison packet to the model with the original source IDs and an instruction to treat the excerpts as leads to verify, not as proof of completion. The ordinary first-pass sample remains capped at twenty-four items, and the quick turn still uses one model call. The page must still identify its coverage as partial.

This is an evidence-selection fix, not a promise that every generated insight is right. A synthetic regression holds the earlier choice and reversal outside the last twelve turns, checks that the quick model receives both original IDs, and checks the bounds. A coding-only private quick run then put the direction change in its lead and Insight, with the key claim supported by the original message. It also attached a weaker citation to a broader lead sentence. The mail connections timed out before a fresh init could complete, so the installed first-run experience and mixed-source claim accuracy still need review.
