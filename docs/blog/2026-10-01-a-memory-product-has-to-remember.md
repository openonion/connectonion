# A memory product has to help its owner remember

The first redesigned REM preview looked more composed than the old Wiki. A
person had cited facts, the People sheet could be sorted, and the night had a
graphic of its runs. Yet the owner still returned to a page that began with a
machine's activity. It answered how much REM processed before it answered what
the owner needed to carry into the day.

That mismatch made us write down the product promise rather than keep polishing
components: REM works while the owner sleeps, joins related context, and helps
the owner remember it. The next preview moves a few current memories to the
first screen, shows one link already present between pages, and gives an older
memory as a question. Processing counts move a little further down, where they
remain useful for checking the run.

The new screen also exposes what we still cannot honestly say. The run log
knows that a page was rewritten. It does not know whether the statement on the
card is new, corrected, or simply phrased differently. Revealing an answer
does not show that a person retained it. The release uses narrower language
and tracks the missing claim comparison and durable recall as separate issues.

We reviewed an invented notebook on desktop and phone, with the former and
current home side by side. The important change is the order of attention: the
owner sees context and an invitation to remember before the file cabinet.
The remaining work is larger than the home. A ranked audit now points to the
noisy memory corpus, fragmented owner identity, article-shaped detail pages,
weak retrieval, and the live question and correction flow. Each needs its own
evidence and acceptance run before the product earns a mature label.
