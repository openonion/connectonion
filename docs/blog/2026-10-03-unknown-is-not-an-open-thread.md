# Unknown is not an open thread

A memory can be wrong without inventing a name or date. In a private first-run
trial, one Project page said no pending work was confirmed and that older
requests had unknown status. It placed that uncertainty under **Open threads**.
The reader showed an **OPEN** badge on the Project page and counted the sentence
on Home. A person scanning the list could reasonably read it as a task.

The same trial exposed a source problem. Nine Project candidates cited the
investigation's coverage summary instead of original sessions or files, and
the source audit refused them. The runner had also been adding a coverage
citation after the model wrote a page. We removed that insertion and put a
specific original-source check at the final Project writing step. The first
recheck looked better and was accepted, but an independent review found that
file citations outside the mapped Project had been removed while an uncited
diagram and command remained. We stopped the release and changed Project
promotion to ask for a repair instead of dropping those citations.

A second recheck kept five original session citations and removed the diagram
and command. Reading all five source dialogs still found claims those sources
did not support. We added a bounded, read-only claim audit at promotion: it
checks the draft against its adjacent originals and preserves the previous
page if the claims fail. The same problematic draft was refused in a real
audit run with five concrete findings.

For pages already written, the reader now keeps “no confirmed pending work”
out of the open list and count. The Project writing instructions make the same
boundary clear before the next investigation. We checked the actual notebook
and a synthetic browser case at desktop and phone widths. The final Project
recheck and Person pages still need source review; other written types also
showed attribution limits in the sampled audit.
