# The page that led with "Unknown"

The owner opened their wiki, the local snapshot that finally loaded, and said
the pages looked crude. The type was fine. The sidebar was fine. Dark mode was
fine. So what was crude?

We rendered their own notebook, 938 pages, and read it the way they would. A
project page was ten headings, each followed by the same line: "Unknown — not
investigated yet". A person page opened with eight contact rows, six of them
"Unknown", and the one real fact, two emails in July, sat under "History"
below all of them. The contents page listed people in alphabetical order of
their email addresses, so it began with the ones that start with digits.

None of that was a styling problem. The mapper writes every heading on purpose:
an Unknown is the next thing to go and find out, and the notebook is its own
work list. The reader showed the work list and called it the page.

So the page now reads each record for what it knows. Known facts come first.
The headings still empty are named once, at the foot, next to the command
that fills them. Each page carries a plain tag: Mapped, Some findings or
Investigated. The Markdown underneath is untouched.

The first version got the tags wrong, which taught us more. It counted
"Sources" and "Uncertainties" as findings, so it called nearly every page
partly investigated. Then every organisation turned out to have a "Who they
are" line that said "Domain candidate; organization identity unverified",
which is a placeholder that happens to be a sentence. Once the page's own
status line decided the tag, the real count appeared: 213 pages with
something to say, 725 outlines. A test built from the mapper's real output
then caught one more mistake. An outline written today was outranking a real
conversation from last week, because both counted as "recent".

The lesson: a page looks crude when it answers the wrong question first.
Before touching the colours, ask what the reader came to find out, and
whether the page says it before anything else.
