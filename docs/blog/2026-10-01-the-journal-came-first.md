# The journal came first

A fresh `co rem init` writes three project pages before it hands the notebook
back, and on the owner's Mac it chose connectonion, `one`, and `journal`.
`journal` is the owner's private diary repository. Its page recorded what the
owner had asked Codex to do there, including requests to leave a hometown name
and a family name out of an entry. Meanwhile LayeredVisions, with 28 sessions,
realtime-voice-chat with 23 and browser with 17 had no page at all.

The queue was doing what it said: recent projects first, newest first within
them. The journal is touched almost every day, so it was always newest. The
order measured how recently a folder was opened, and a diary is opened more
often than a codebase.

So the order is now the number of the owner's own messages in each project,
with recency only breaking ties. A folder whose name or path says it holds the
owner's life rather than their work (journal, diary, private, personal,
日记) is still mapped, and its sessions still count toward everything else.
Its page is just never written unasked. Neither the first run nor the daily
round queues it. The owner can still investigate it by name.

The same run made a project page called `install-github-cli-gh-on-this`.
Codex names a scratch folder after the first request typed into it, and this
one held two sessions about installing a command-line tool. Scratch folders
already joined by name across days, because real work happens in them too:
realtime-voice-chat lived in a dated folder for weeks. A scratch folder with two
sessions or fewer is now a one-off task, recorded among the dropped folders
with that reason, and not a project.
