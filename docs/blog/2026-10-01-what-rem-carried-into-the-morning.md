# What REM carried into the morning

You come back to a memory product after a night away. The first question is
simple: what should I know now? The reader answered with how many items it had
read and how many pages it had rewritten. Those numbers were accurate, but they
put the machine's work ahead of the owner's memory.

We moved the remembered context to the first screen. Up to three pages touched
by the latest pass now offer a current statement and a path to their sources.
An existing page link appears as connected context. A second card asks about an
older relationship and waits for the owner to recall it before revealing the
answer. Open threads remain close; the run counts are still there when someone
wants to inspect the night.

The distinction between a changed *page* and a changed *belief* matters. A run
log can prove that a file was rewritten. It cannot prove that the statement in
the new file was discovered overnight. The new brief therefore says the page
was updated and shows what the page currently says. We opened a separate issue
for claim-level comparison, with before and after evidence. Likewise, the
reveal button does not pretend to measure learning; a durable recall loop needs
the owner's feedback over time.

An invented notebook let us compare the earlier and new first screens without
exposing anyone's correspondence. On desktop and phone, the new hierarchy makes
the morning question visible before the file cabinet. Browser checks cover the
reveal control, keyboard use, source links, dark mode, and phone overflow. The
person and project pages remain too document-shaped, and the reader still
cannot answer a question. The next design passes have explicit issues rather
than being hidden behind the darker card.
