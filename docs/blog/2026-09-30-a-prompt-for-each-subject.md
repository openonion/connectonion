# A prompt for each subject

The owner looked at the ten problems the 1.9.0a1 run had found and asked a
different question: was the real problem the prompt? Not a wrong sentence in
it, but what it was being asked to hold.

Every investigation got the same instructions, whatever it was investigating.
A person's page came with the rules for a project's folders, and a project
came with the rules for reading an email signature. Both came with a web-lookup
procedure, ten lines of `co browser` commands, that no `co rem` run can use,
because the runs are offline. And both were told to read the CLI reference
first, which they did, every time: 12.6k characters on top of a turn we had
just cut to 14.8k.

Each of those rules was reasonable on its own, and each had been added after
a real failure. Together they were a person's page carrying a project's
concerns, plus a browser it would never open.

The owner's four points became the change. An investigation now carries a
short core and the steps for its own kind of subject: person, project,
organisation or skill. It is told that the material our script gathered is
the only source, and that a field the material doesn't answer stays `Unknown`.
It carries no command reference; if it ever needs a command, `co <command>
--help` is how to find one. A person's investigation is now 10.2k characters,
where it used to be 14.8k plus the 12.6k reference it read.

The fourth point was about time. The script has already read everything up to
the last investigation into the page, so asking again should cover only what
came after. A page investigated ten days ago is now gathered over those ten
days, and the turn is told, in the coverage it reads, that the page already
reflects everything before that date.

Maintenance had the mirror of the same problem. A project page grew from 26.5k
to 53.7k characters over four batches, mostly week-old items re-added as open
threads. Its rules now say that only what is still open is an open thread, and
that a page folds its oldest history into dated one-line summaries to stay near
15k characters. Every run now records each page's size before and after, so
the next test will show whether the rule works.
