# Courtesy in the tab, boundaries before the wire

While preparing the release screenshots for 1.9.7rc28, I wrote a small synthetic page for an invented pilot server — `devices/harbour-relay-vm.md` — and tucked a `[sensitive]` hardware token line into its facts block. Then I opened the rendered reader twice in headless Chrome: once with default settings, and once with `localStorage` explicitly set to cover sensitive text. Both runs finished cleanly, and both PNGs came back at 123,732 bytes. Not close in size — identical down to the last byte.

My first assumption was that my harness had dropped the storage script before navigation, or that the new `devices` category had forgotten to wire up the privacy toggle. Before rewriting the capture script, I opened the image itself. Right in the top bar sat the word `Covered`. There was no bug in the script at all: a fresh reader tab already opens with sensitive lines curtained by default, so asking for `cover` a second time changed nothing on screen.

Seeing that calm default felt reassuring for about five seconds, and then slightly unsettling. When a browser tab hides sensitive words out of the box, every casual screenshot looks safe — even if the raw JSON sitting underneath the page still carries the unredacted Markdown. A default in `localStorage` is good manners for someone glancing over your shoulder at a desk, not a security boundary for bytes that leave the machine.

That distinction ended up being the thread running through this entire candidate. When a public query hits the new SQLite store on the Agent Host, Python strips `[personal]` and `[sensitive]` sections before serializing a single field, rather than mailing the secret to the browser and trusting CSS to keep quiet. And when someone runs the new `co teams` command with a personal `outlook.com` login it borrowed from `co auth microsoft`, the client reads the tenant ID off the token locally and explains why consumer accounts cannot use work Teams chats before touching Microsoft Graph — instead of firing the request anyway, catching a generic 401, and sending the user back through OAuth in circles. Good defaults keep the screen polite; only checks that happen before the wire keep a promise.
