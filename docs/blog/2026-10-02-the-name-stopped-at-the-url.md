# The name stopped at the URL

The owner asked whether the Wiki rename had reached the latest preview.
It had: the published 1.9.0a18 wheel contains `connectonion.rem`. But its
`co rem open --live` still points to a URL ending in `/wiki`. The browser
calls the page “Rem,” while the product decision calls it “co rem.” The
README once introduced the feature; its latest rewrite removed that section
and left a memory icon whose tooltip still says `co wiki`.

The first rename deliberately left O Chat's route outside the Python
repository. A later frontend change repaired the instructions without moving
the route. Each change worked within its repository, and the gap survived
between them. Searching the README was not enough either: its icon block is
generated by the homepage, which would put the old command back on the next
refresh.

The repair follows a link from its source to its destination. The homepage's
connection data emits `co rem`; the README explains the opt-in preview and
its local notebook; the SDK generates `/rem`; O Chat owns that page and
redirects `/wiki` bookmarks, preserving their query and page fragment. The
docs navigation and search lead to the current guide. Published histories
and migration instructions still name the old command where that name is
needed to understand an upgrade.

A public rename does not require invalidating an owner's existing session.
The signed `WIKI_READ` transport and stored reader session remain compatible
with current Hosts. The browser wraps its frame exactly as before, including
its no-network policy and owner gate. Changing those boundaries to tidy up
spelling would add a different migration to a branding repair.

The SDK reader, signed-read and CLI checks passed 111 tests locally. Browser
checks cover the new route, owner refusal, offline recovery and old bookmarks
on desktop and phone. The frontend route must be deployed before a new SDK
preview starts sending people there; a passing local test is not proof that
an existing published wheel has changed.
