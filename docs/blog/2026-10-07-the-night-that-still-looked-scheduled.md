# The night that still looked scheduled

The phone said the next pass would run tonight. The notebook's newest saved
run was five days old. Its launchd job was installed and loaded, but the last
exit code was one. REM had the machinery of a night, without evidence that
the night was carrying context forward.

That difference changes the design review. A new card can make a failed run
visible, but a scheduled label still cannot promise successful maintenance.
The prefix-integrity guard is doing useful work: it refuses to treat a
rewritten session as an append. The product needs a recovery boundary around
that one source, and a truthful account of what continued and what did not.
Silently dropping the checkpoint would erase the evidence we need to recover.

The morning has a similar gap. In the real phone view, the recall prompt began
1,583 pixels down; the Project's connections began beyond 2,000. Links exist,
but the owner must first read enough of a document to find them. A written
Person can even say its sender's human identity is unresolved while wearing
an Investigated badge. Completion and confidence need separate meanings.

We recorded the ten current problems using aggregates and local private
screenshots. No overflow appeared in the ten sampled frames, but no-overflow
is not the experience test. The next proof is one safe night that continues
past an isolated source failure, one supported change in the morning, and a
short path to its evidence or correction. Until then, shipping another
preview is progress in distribution, not proof of a mature memory product.
