# The first page was only a sample

The first REM page should help a new owner understand what the product found. In an isolated five-day init, that page appeared quickly and the command exited successfully. The full owner investigation had not run: the account was already above the configured weekly safety floor. The page footer still said "investigated," and the command's next step was to open it. A reader had no reason to know that the page covered only the short first pass.

The safety floor was doing useful work. Raising it just to make the first screen look complete would spend an account's remaining allowance without consent. The defect was in the promise made by the saved page. A quick pass can hold useful cited leads, but it cannot stand in for the full source window.

The page now records a "quick sample" pass with its day window. The reader names that state on the page and offers the command to finish the owner investigation. The CLI result calls it partial and returns the same next action. If someone runs init again after a quota reset, it reuses the saved sample and attempts the full pass; the estimate counts only the turn still needed. A completed full pass then changes the state to investigated.

This change says what was actually reviewed. It does not decide whether a generated lead is consequential or supported by its cited source. That question needs a separate source audit and remains part of the first-run quality work. The observed five-day run proves the partial-state gap; synthetic browser tests prove the state is readable at desktop and phone widths. Neither is an all-person quality claim.
