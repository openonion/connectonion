# Why wiki-source-whatsapp says what it says

The rules live in `connectonion/useful_skills/wiki-source-whatsapp/SKILL.md`,
appended to a stage's instructions when the material comes from WhatsApp. This
file holds the reasons; it is not loaded at runtime (#1851). That Skill was
nearly all rules already, so little moved.

## Only chosen chats reach the batch

The phone is in many more groups — family, unrelated communities, other
clients — and none of them is in the batch. Absence from the batch therefore
says nothing about the user's life.

## The other side is a person

As with mail, `role: other` messages are a real correspondent's words, and
their page is written from them.

## Why the agent's replies are missing

When the user's assistant answered in the chat, that answer is execution, not
the user — the same rule as coding sessions. Reconstructing it would put words
on a page that neither the user nor the other side wrote.

## Groups are clients' rooms

Most business WhatsApp groups are one client each, and the same user often
discusses the same topic with several clients. Carrying a price or a guest
across groups leaks one client's business onto another's page.

## Short messages

WhatsApp is terse. A decision is often only a short "yes go ahead" from the user
after a longer proposal from someone else, so the proposal has to be read as the
content of the decision.
