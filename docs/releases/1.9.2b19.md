# ConnectOnion 1.9.2b19 (beta)

## Install this preview

Stable remains 1.9.1. Install this opt-in beta by exact pin:

```bash
python -m pip install --upgrade 'connectonion==1.9.2b19'
```

## One host, whichever way you start it

Set up an agent once and it serves everything:

- **`co host`** serves the agent in this directory. It runs `agent.py` with the
  Python co itself runs on, so it works on a machine set up with the one-line
  installer, where the system `python` cannot import connectonion (#2438).
  `co create` now tells you to run it.
- **REM on every host.** `python agent.py` and `co deploy` serve your REM pages to
  you, as `co ai` always did. `rem: false` in `.co/host.yaml` turns it off (#2439).
- **One way to answer channels.** `co ai` hands the channels in `listen:` to the
  host, which answers them for every way of starting, instead of running a second
  consumer of its own.
- **Docs that match the code**: what one host serves, the real `host()`
  signature, `rem:` and `listen:` in host.yaml, and a guide to the five things
  "discover" means in co (#2440).

## Verification and limits

- Found by a 1.9.2b18 test on an empty Ubuntu environment and an audit of the
  host code. The new tests failed on 1.9.2b18 and pass.
- The handoff install floor stays 1.9.2b18: nothing in a handoff changed.
- A host started on a server with no `~/.co/rem` answers REM requests with "not
  available on this Host", as before.
