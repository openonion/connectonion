# 1.9.0a3 — 1.9.0a2, published

An opt-in preview of 1.9.0. Stable is 1.8.9.

1.9.0a3 is **1.9.0a2 as it was meant to ship**, plus the fixes below. The v1.9.0a2 tag was pushed, but
its release run failed one test and nothing reached PyPI: the test marked a
person investigated three hours before "now" and expected a one-day window,
and the run started at 00:08 UTC, when three hours earlier was yesterday. The
code was right; the test now runs at a fixed noon.

Everything in it is described in the [1.9.0a2 notes](1.9.0a2.md):

- The notebook is **co rem** everywhere, and a co wiki notebook, its schedule
  and scripts carry over; `co wiki` names the co rem command and runs nothing.
- **A first run you can read:** `co rem init` maps with no model, prints your
  page, then writes it and your recent projects' pages, cost stated first.
- **Project pages** from the messages you typed to Codex and Claude Code;
  **people** investigated recent correspondents first, from new mail only; a
  **daily round** that finishes once and follows what is new.
- Addresses held for review, quiet nights that cost nothing, the model's tier
  measured, and a help page that moves nothing.

## Also fixed since 1.9.0a2 was tagged

Found running 1.9.0a1 on a copy of the owner's real notebook:

- A page's handles are read without their citations, and only whole addresses
  go to the mail server; a cited handle had made Gmail return 677 unrelated
  mails (#1954, #1970).
- The investigate Skill reads the 12.6k-character CLI reference only before it
  runs a `co` command, so a turn carries ~15k of instructions, not ~27k (#1960).
- A finished task keeps only its result and candidate; copied mail is removed
  and old folders are scrubbed (#1958).
- `status` and `doctor` check that the installed schedule really runs this
  notebook (#1964); the status line no longer names the evidence layout as a
  source (#1962); every stage records its instruction size (#1959).
- A project page lists a worktree as its main checkout first, so investigation
  reads the project and not a stale copy (#1955, #1965).
- Each subject gets its own investigate prompt, the gathered material is the
  only source, a page investigated before reads only what is new since then,
  and maintenance keeps a page near 15k characters (#1956, #1971).
- An org page asks the mailbox for its domain and reads the init archive
  (#1963, #1967).
- `co rem sync` names the daily cap where you look: dry-run shows attempts left
  and the reset, a refused run stays in logs, and Ctrl-C says what finished
  (#1957, #1969).
