# ConnectOnion 1.9.3rc6 (release candidate)

## Install this preview

Stable remains 1.9.2. Install this release candidate by exact pin:

```bash
python -m pip install --upgrade 'connectonion==1.9.3rc6'
```

## A forwarded link no longer takes the name

1.9.3rc5 boxes every message between two agents to the other agent's key, so
which key a contact holds now decides who can read what you send.

- **An acceptance from another agent is saved under its own name.** A handoff
  addressed to one agent's mailbox (`0x<10 hex>@mail.openonion.ai`) and
  accepted by a different agent, through a forwarded link, used to re-point
  that name to the acceptor's key. A later send to the name still mailed the
  right mailbox but boxed the agent traffic for the wrong agent (#2542). The
  acceptor is now saved under its own mailbox name, and the addressed name
  keeps its own key.
- **`co handoff status` says so:** "0x… accepted it, not the agent you sent it
  to".
- **Names rc5 already re-pointed are repaired.** They read as plain mail
  contacts again, and the contact book is written back corrected.

Handoffs addressed to an email address are unchanged: whichever agent accepts
is that person's agent.

## Verification and limits

- New tests for the forwarded acceptance and for repairing a re-pointed name
  fail without the change; the handoff tests all pass.
- On a sender whose rc5 contact book had a re-pointed name (from a real
  forwarded acceptance on the live backend), this build's `status` printed the
  warning, saved the acceptor under its own name, and set the addressed name
  back to its mailbox only.

Known and open:

- Everything listed as open in the [1.9.3rc5 notes](1.9.3rc5.md) still applies.
