# ConnectOnion 1.9.3rc49 (release candidate)

Stable remains **1.9.2**; Python **3.11+** and the existing dependency floors are retained.

## REM audit follow-ups (#2802)

- A run whose process ID was reused after a reboot no longer shows as running forever: a record
  that started before the machine's last boot is closed as abandoned. A live scheduled run keeps
  its claim however long it takes, so a second scheduled sync never starts beside it.
- Page stamps, verdict dates, owner refresh and queue cutoffs use the notebook's time zone instead
  of mixing UTC and the machine's local date.
- Merging two pages keeps the kept page's generated blocks, and imported text stays under its own
  section.
- `co rem status` shows the slot the scheduler will actually serve next.
- `co rem investigate --help` says that manual investigations are outside the daily call cap and
  count toward the week.

## Sync, status and the guide say what happened (#2803)

- A missing Codex or Claude Code CLI is named, with its install command, instead of "First run
  needs attention".
- A slot that is not due says why, the Tokens line totals the stages the sync ran, and the
  new-material line says when more mail is waiting. Restart hints keep `--root`.
- The "Start here" guide matches the code; old command aliases no longer promise a past version.

## Release checks (#2800)

- The egress connect-timeout test asserts a shared budget, so Windows' coarse clock no longer fails it.

## Install after publication

```bash
python -m pip install --upgrade 'connectonion==1.9.3rc49'
```
