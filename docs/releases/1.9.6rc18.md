# ConnectOnion 1.9.6rc18 (release candidate)

Stable remains **1.9.5**. Python **3.11+**.

## REM background

- **"Run it again: it moves on" is now true.** `co rem next` has ten minutes to prepare a task.
  One call can pass over several pages before it reaches the one that hangs, and the round was
  saved only when a task was served. The record of the stall named the page's place in the list,
  the saved round was one place behind, and the two were compared for equality: no match, no skip,
  and the next call prepared the same page. The page is now parked by its name, with the reason in
  words, where `co rem status` lists parked pages. It is left out of the rest of the round and
  retried by the existing rule for parked pages (after 20 hours, at most three times on the same
  material). Pages a call passes over are saved as it goes.
- **A turn that only stalled is not completed.** A turn that exits 0 is completed when a task was
  served, a submission was accepted, or its last `co rem next` answered without a task. When its
  last `co rem next` passed the deadline and nothing was served or submitted, the receipt says
  `failed`, `produced_nothing: true`, and why. `co rem status` and Today count these in the
  failure sentence: "the last 3 turns ran but produced nothing". Idle turns are not counted.
  A turn in which no `co rem next` was recorded stays completed and says so.
- **The deadline says where the time went.** The progress line names the step inside the page
  ("Still preparing people/<page>.md: gathering codex sessions (212 s on this step, 240 s so
  far)…"). At the deadline one line lists the seconds of every step, and the turn log keeps the
  same numbers as a `rem.preparation_stalled` event.
- **A person's page no longer reads every coding-session log again.** What the owner typed in
  coding sessions is kept as one window for all pages. The window was discarded whenever a log it
  had read was no longer a plain file, and Codex compresses old logs in place: from the first
  compressed log on, every page read the whole store, and a build ended by the deadline saved
  nothing. A compressed log is now read once more by itself (and decompressed once, not three
  times), a deleted log takes only its own messages with it, and the window is saved as it is
  built. On five generated logs (237 MB), the page after one log was compressed read 429.5 MB
  before and 20.6 MB now; the page after that, 429.5 MB before and nothing now.

Not changed: a log that is still being written is hashed again from its start each time it has
grown, and the first build of a window re-hashes what it has read of a log every 64 MB.
