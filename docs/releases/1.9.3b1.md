# ConnectOnion 1.9.3b1 (beta)

## Install this preview

Stable remains 1.9.2. Install this opt-in beta by exact pin:

```bash
python -m pip install --upgrade 'connectonion==1.9.3b1'
```

## The recipient runs the release that sent it

The line a handoff's recipient pastes tells their agent which co to install.
From 1.9.2b29 through 1.9.2 it still said 1.9.2b27, because the floor was only
raised by hand and nobody raised it (#2512). So every recipient ran b27, which
predates the 1.9.2 permission audit. In a real run on Parrot, `co handoff open`
started its work turn with full access instead of inside the work folder.

- **The recipient installs this release.** The pasted prompt pins 1.9.3b1, from
  that version's own installer.
- **A preview counts as older.** The prompt says so in words, so an agent that
  finds 1.9.2b27 installed upgrades it instead of reading "1.9.2b27" as
  "1.9.2". When the floor is a final release, the prompt adds "its previews,
  such as …b27, are older".
- **It cannot be forgotten again.** A test fails any release whose prompt pins
  a version other than its own (dev builds keep the last release's floor, since
  their own version is on no index).

Checked on Parrot with interactive Codex 0.162.1: a recipient with co 1.9.2b27
pasted the line from a handoff sent by this change, and Codex upgraded co,
accepted, did the work and sent the result back.

Handoffs already sent keep the prompt they were sent with. Send again from this
release for the recipient to get it.
