# 1.9.7rc7

A reader polish batch and the WeChat upgrade fix.

## Reader
- **Record pages open at one width.** A skill page used to render in a 1160px frame offset left, with its Source box floating in a dead right margin, while every other record kind sat in an 800px frame. Skill pages now use the same frame — header and reading column aligned like an org or project page ([#3231](https://github.com/openonion/connectonion/issues/3231)).
- **A project page's "N open items are in Today" opens the filtered view.** It used to open an empty, off-screen panel; it now opens the Waiting view filtered to that project (the same filter the project's own chip uses), with an honest empty state when nothing is open.
- **Calendar titles clamp.** A long event title (a pasted mail quote) wrapped to a four-line wall in the day-grid and the phone day-list; it now clamps to two lines, with the full text still on the event's detail panel.
- **The empty Keys page leads with one-click import.** With no keys yet, the Chrome / Edge / Brave / CSV importers show first as the primary action instead of being collapsed behind the manual form — import, don't hand-type.
- **A topic link review names the page, not its file path.** The question read "Does people/…-fb3e61a907.md concern this topic?"; it now names the page by its title.

## WeChat as a co rem source (upgrade fix)
- On a machine that already had the wechat source before it became default-on, the stored subscription kept `Consented: No`, so the default never took effect on upgrade — and the seed and read paths gated on different conditions, so people pages were created but never filled. Now, when the WeChat keys are present (captured with `co wechat key capture`) and the source has not been removed, consent is implied, and seeding uses the same gate as the reader. The night both **seeds** new WeChat contacts as people and **fills** them with their chat. Undo with `co rem sources remove wechat` ([#3289](https://github.com/openonion/connectonion/issues/3289)).
