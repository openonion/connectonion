# ConnectOnion 1.9.3rc13 (release candidate)

> **Compatibility:** Python 3.11+; Pillow 13.0.0+, pypdf 6.21.2+ and cryptography 50.0.2+.
>
> **Scheduling:** Native Codex Schedule migration is not included. Existing scheduling stays in place. [Verification status](https://github.com/openonion/connectonion/blob/main/docs/acceptance/rem-native-source-2026-10-22/README.md).
>
> **Intel Mac:** Install the native build tools described below before installing this preview.

Stable remains 1.9.2. This preview requires Python 3.11 or newer.
Install into an isolated environment with a supported interpreter:

```bash
uv tool install --python ">=3.11" --force 'connectonion==1.9.3rc13'
```

Or, from an existing Python 3.11+ environment:

```bash
python -m pip install --upgrade 'connectonion==1.9.3rc13'
```

## REM leaves your active Codex history alone

REM's internal model calls previously remained as ordinary Codex conversations,
which crowded out your own recent work. REM now uses Codex's native thread
archive after each call, including a failed call while the provider is responsive.
The thread ID and trace remain available; explicit resume unarchives the same
thread first and archives it again afterward. Ordinary interactive conversations
are unchanged. Existing history is not bulk-archived.

If archival fails, the CLI reports the failure with the provider thread ID,
message, usage and completed-turn status where available. A forced cancellation
or process crash can leave a thread in active history.

## Scheduling boundary

This candidate does **not** migrate to Codex App Scheduled. REM's macOS launchd
schedule stays in place. Codex CLI 0.163.0's generated App Server protocol has no
scheduling management method; the desktop app's legacy automation files are not
a verified replacement for that API. Changing the trigger alone also does not
prevent the inner REM calls from creating active threads.

See the [local acceptance record](../acceptance/rem-codex-history-2026-10-22.md)
for real Pro checks, independent review and remaining UI coverage gaps.

## Security dependencies and Python compatibility

Pillow now requires version 13.0.0 or newer, and pypdf 6.21.2 or newer.
These floors are in the published package metadata as well as the lockfile,
so installation into an existing environment cannot retain the affected older
versions. The new preview requires Python 3.11+, matching Pillow 13. Python
3.10 reached upstream end of life on October 1, 2026. Existing installations
are not modified, but must upgrade their interpreter to use this preview.
The shell installer selects a supported Python using uv and leaves system
Python unchanged. CI now covers Python 3.11, 3.12 and 3.13.

Cryptography also requires 50.0.2 or newer. The former Intel macOS <49 cap
retained known vulnerabilities and has been removed. Upstream no longer ships
Intel macOS wheels. Intel Mac source installation requires Xcode Command Line
Tools, Rust and OpenSSL build dependencies. With Xcode Command Line Tools and
Homebrew already installed, prepare the build tools in the same shell:

```bash
brew install rust openssl@3 pkg-config
export OPENSSL_DIR="$(brew --prefix openssl@3)"
```

Then use the preview installation command above. uv selects a supported
interpreter without replacing system Python. Linux, Windows and Apple Silicon
use upstream wheels where available.
