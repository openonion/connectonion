# ConnectOnion 1.8.4a2 — Gmail receipt recovery preview

Prepared 8 September 2026. This opt-in preview fixes the real Gmail acceptance
issue found in 1.8.4a1. Stable remains **1.8.3**; final 1.8.4 is not released.

Gmail can replace the Message-ID supplied by the reviewed MIME. New draft sends
also carry a dedicated attempt marker. If a response is lost, recovery first
tries Message-ID, then scans at most 100 recent sent-message metadata records.
Only one exact marker match on a complete result page can become a receipt.
Missing, duplicate or incomplete results remain uncertain and never trigger a
blind resubmission. Older records without a marker retain their existing guard.

QuickConnect login now requests the verified regional HTTPS relay when direct
addresses fail; the interactive prompt accepts a QuickConnect ID or HTTPS URL.
Credential-free discovery reached a real NAS; authenticated file acceptance is
still pending. The 123 Synology regression checks pass.

The first `co` screen now includes global setup, `co ai`, explicit project
configuration examples and aligned command descriptions.

The acceptance harness now reports each post-send stage, distinguishes stored
content from inbox routing, and resolves macOS temporary paths before checking
that downloaded attachments stayed in their destination.

Validation: **8,568 Core tests passed**, 22 skipped and 184 live tests excluded.
Separately, the installed local fix passed the full real Gmail/Drive journey:
attachment source round trips, stale-review rejection, exact stored body and
attachment hashes, one self-send, lost-receipt recovery with resubmission forbidden,
mailbox actions and two private collision-safe downloads. The test fixtures were
cleaned. Twenty-six local browser flows, loopback storage acceptance and six
configured provider reads also passed. Detailed limitations and sanitized evidence
are in [the acceptance record](../acceptance/1.8.4-live-followup/README.md).

Physical Synology acceptance remains outstanding. The browser flows use a scripted
Host, and hosting acceptance uses a local emulator; no cloud resources or production
hosting deployment are implied. This release addresses Core issue #1460.

Install explicitly after publication:

```bash
python -m pip install --upgrade 'connectonion==1.8.4a2'
```

Ordinary stable installation remains on 1.8.3. To return to stable:

```bash
python -m pip install --upgrade 'connectonion==1.8.3'
```
