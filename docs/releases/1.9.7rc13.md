# 1.9.7rc13

Release candidate for 1.9.7. Stable remains 1.9.6.

## Adding a source onboards it (#3331)

### `co rem map` and `investigate --source` (#3334)

- `co rem map [people|orgs|projects|knowledge] --source NAME [--dry-run]` builds pages from one source. It calls no
  model: it creates pages for anyone worth a page who is not in the notebook yet, and adds the new handle to an
  existing page whose full name matches. `--dry-run` prints what it would create or merge and writes nothing.
- Each source declares the kinds of page it yields: gmail/outlook yield people and orgs, wechat yields people,
  codex/claude-code yield projects. Asking for a kind a source does not yield is refused ("wechat yields: people",
  exit 2, nothing written).
- After a map, the next step is printed: `co rem investigate people --source NAME --new`.
- `co rem investigate people --source NAME [--new|--existing|--all] [--limit N] [--list]` runs the pages that source
  reaches by handle, new ones first.
- `co rem sources` shows what each source yields and now lists wechat.

### Adding a source maps it (#3335)

- `co rem sources add NAME` maps an approved source right away.
- The night re-maps WeChat (its contacts keep growing) and any local source that is new or widened. Mail and coding
  sources are mapped by `co rem init`, `co rem sources add` and `co rem map`, not at night.
- Pages a source created, or gave a new handle, go first in the people queue until each is investigated; a page
  that gained a handle is appended to, never rewritten.
- `co rem sources` and `co rem status` show, per source, when it was mapped, what it made and how many pages are
  still to investigate.
