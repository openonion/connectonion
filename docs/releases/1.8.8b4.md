# 1.8.8b4 — Claude Code terminal in an OIP Work Room

This opt-in beta adds a native Claude Code Station to the 1.8.8 preview line.
Run `co claude --cwd /path/to/project` to start Claude's normal terminal and
print its O Chat Work Room URL and private pairing code. A paired browser can
watch the same session, take control, send a direct message to Claude, and
return control to the terminal. `--resume` keeps an existing Claude session;
`--no-share` runs the terminal without a Work Room.

The Station uses scoped Claude Hooks for session and activity facts and reads
the exact native transcript for visible messages. Host stores and streams these
as OIP provider events. Browser control and direct input are signed, tied to the
paired session, and rejected when the terminal owns the writer lock. A browser
file edit inside the selected workspace waits for the authenticated owner's
approval. Unknown actions, shell commands, and paths outside that workspace
are denied. Tool input is not stored in the OIP trace.

Install this exact beta with:

```sh
python -m pip install --upgrade 'connectonion==1.8.8b4'
co claude --cwd /path/to/project
```

The native terminal process must stay running for this beta's Work Room to be
available. The browser front end requires O Chat with `@connectonion/react`
0.4.4-rc.4; see [O Chat PR #245](https://github.com/openonion/oo-chat/pull/245).
The CLI, Host, SDK, and browser were tested together locally with Claude Haiku:
terminal observation, browser takeover, direct continuation, and return to the
same terminal session passed. Focused Core tests and SDK tests passed, as did
desktop and 375px browser tests. The browser file-edit Hook response has a
focused unit test; a live file-edit approval was not part of the Haiku journey.

Stable remains 1.8.7. Personal Wiki remains in preview, with its full quality
acceptance targeted at 1.9.0. This beta does not change that gate.
