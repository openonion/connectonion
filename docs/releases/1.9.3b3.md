# ConnectOnion 1.9.3b3 (beta)

## Install this preview

Stable remains 1.9.2. Install this opt-in beta by exact pin:

```bash
python -m pip install --upgrade 'connectonion==1.9.3b3'
```

## The handoff's thread, listed in Codex

1.9.3b2 added the sender's conversation to the recipient's Codex as a thread of
its own. A review in a Codex that had been used before found two gaps.

- **It was not in the list.** Codex 0.162.1 lists `/resume` and the app's
  sidebar from its own database, and copies new conversation files into it
  only once, the first time Codex runs. So the thread opened with
  `codex resume <id>` but was missing from the list. Accept now asks Codex,
  through its own app server, to read the thread once by id, and that adds it
  to the list. If `codex` is not on the PATH, the line names only
  `codex resume <id>`.
- **The agent did not mention it.** One Codex receiver ended its report at
  "Sent Aaron the completed patch". `co handoff done`, the last command before
  the report, now prints the line again and asks for it word for word.
- Codex's conversation files are named by local time, as Codex names its own.

The 1.9.3b2 notes said the thread was listed in `codex resume`'s picker on
Parrot. That held only because the thread had already been opened by id.

The prompt now pins 1.9.3b3. Handoffs already sent keep the version they were
sent with.
