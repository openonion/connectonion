# ConnectOnion 1.9.0a26 (preview)

[Install this preview](#install-this-preview)

## Written notebooks reopen faster

`co rem open` rebuilds a private HTML snapshot before opening the local reader.
In a notebook with many investigated pages, relationship inference and PDF
source previews were doing repeated work. This preview checks for a literal
name before the original boundary-aware relationship expression and stops PDF
preview extraction once its bounded excerpt is complete. Investigation still
reads full attachments. Notebook files are not rewritten by this change.

On one private 810-record notebook with 227 written pages, an independent AI
role-based reviewer measured the tagged a25 reader at 41.92 seconds and this
candidate at 8.78 seconds on the same machine. All 810 record paths and texts,
2,504 relationship edges, and 738 source contexts matched, including seven
attachment contexts. Output permissions stayed private (0600). This is one
machine and notebook, not a general speed guarantee. The reviewer opened
actual desktop and phone reader states, including Full memory, source dialogs,
and a PDF-backed person; no P1/P2 regression was found in those samples.

## Existing memories stay visible when updates are off

The reader now labels a missing background schedule as **Background updates
off** when the notebook already has mapped or written pages. It keeps `co rem
start` as the next action and leaves those memories readable. A genuinely
empty notebook still shows the initial **Not started** guidance.

## The preview install command matches the package

The package README's exact `co rem` preview pin is checked against the version
being built. The a25 PyPI description had retained an older a22 command; this
published a26 package's metadata includes the a26 command. The already uploaded a25
description remains historical metadata.

## CI feedback

The full CLI help audit runs once in the release/test workflow while ordinary
Python 3.10–3.13 suites keep the shorter help checks. In one comparable PR
pair, Tests wall time fell from 11.77 to 9.68 minutes and summed runner time
from 61.77 to 52.00 minutes. Python 3.12 coverage remains the critical path;
the broader CI timing issue is still open.
