# 1.8.9b6 — Offline Wiki maintenance can read its staged files

An opt-in preview on the 1.8.9 fix line. Stable remains 1.8.8.

## Fixed

- The offline Wiki instructions now allow sandboxed reads and writes of staged
  local files while continuing to prohibit network and source-app actions.
  Luna previously refused a local-file batch because “offline” was described
  as “no shell,” and the runner counted its unchanged result as completed.
- An unchanged maintenance batch now requires a completion receipt naming the
  reviewed sources and the reason for no change. Missing or invalid receipts
  fail without advancing source progress.
- Markdown numbered source entries such as `1. source-id` are normalized to
  the Wiki's `[1]` citation format inside Sources before the existing citation
  checks. Claims and source identifiers are not rewritten.

The focused Wiki suite passed (348 tests), as did the pull request's Python
3.10–3.13 CI matrix. A synthetic Luna evaluation covers the refusal and a
conflicting-source retest; it does not establish a production mailbox success
rate. No production Wiki pages were promoted as part of this release.

## Known limits

- A model can still submit an inaccurate no-change receipt. The receipt makes
  an unreviewed no-change distinguishable from completion but is not proof of
  source comprehension.
- Existing broad-suite failures outside Wiki remain open; this preview does
  not claim to fix them.
