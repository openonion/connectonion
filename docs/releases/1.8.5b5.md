# ConnectOnion 1.8.5b5 — beta

Beta, 14 September 2026. One change on top of `1.8.5b4`, plus a platform that
now works and did not before.

Stable stays **1.8.4**. This is not Latest and needs an explicit pin or
`--pre`:

```bash
python -m pip install --pre connectonion==1.8.5b5
co --version
```

## Change

**Asking for the paid engine fetches the client it runs on.** The route to the
WTF Browser was three commands, and you learned the second one by failing:

```
co browser --engine wtf tab open work
→ onionwright_missing: Run `co browser install-onion`
→ Could not install Onionwright: this Python is externally managed...
→ co browser install-onion --break-system-packages
```

Every one of those errors is well written — `b4` fixed the middle one. But the
first asks the caller to decide nothing: the paid engine cannot run without its
client, and there is no configuration in which you want one and not the other.
An error that offers no choice is not an error, it is a missing step.

Now:

```
co browser --engine wtf tab open work
→ The WTF Browser needs its private client, which is not on PyPI. Fetching it…
  Installed Onionwright 0.0.14 from the signed OpenOnion release.
  work
```

The rule that predates this holds: importing ConnectOnion, or taking the free
engine, still never mutates a Python environment. Only a typed `--engine wtf`
fetches anything — `--engine auto`, `--engine system`, and even
`--engine wtf help` install nothing, and a failed fetch reports it without
sending the command to a daemon that could not serve it.

`--break-system-packages` stays opt-in one layer down. Spending money,
overwriting something, or overriding a guard someone set on purpose are the
steps that should stay manual.

## The paid browser now runs on Intel Macs

Not a change in this package — a release that had been missing. `co browser
--engine wtf` on a macOS x86_64 machine answered `artifact_unavailable`, because
no `darwin-x86_64` object existed in the production catalogue.

The bytes were never missing. They were built and staged on 2026-09-04 and never
promoted, because that day's native gate failed at the renewal arm with all seven
cases reporting `before=False`. The same gate failed identically for arm64 that
day; arm64 was re-run on the 5th, passed, and was promoted. Intel was never
re-run.

The re-run happened on 2026-09-13 on real Intel hardware: 12/12 startup and 7/7
renewal, `before=True` throughout. The object was promoted, verified after
promotion, and added to the production paid catalogue (oo-api v0.1.17).

Verified on the machine that reported it — an i9 MacBook Pro now resolves
`engine=onion`, `fallback=False`, artifact
`chrome/151.0.7922.222/darwin-x86_64-enterprise.tar.zst`, with a real paid
session.

## Known limits

Unchanged: the no-loss-across-a-reconnect gate in #1462 has not passed, which is
why stable is still 1.8.4 — that gate is the Feishu inbox, not the browser, and
nothing in this release moves it. A chat message can command the agent and there
is no sender allowlist until 1.9. A browser that exits on its own takes the tab
registry with it (#1513, targeted 1.8.6).

The private client is still distributed through a signed manifest rather than
PyPI, where only a name-reservation placeholder lives. That policy is being
revisited; this release does not depend on the outcome either way.
