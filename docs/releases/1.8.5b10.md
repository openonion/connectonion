# ConnectOnion 1.8.5b10 — beta

Beta, 15 September 2026. `co auth lark` creates an application and returns its
secret. **This corrects 1.8.5b9, which said it could not.**

Stable stays **1.8.4**. This is not Latest and needs an explicit pin or
`--pre`:

```bash
python -m pip install --pre connectonion==1.8.5b10
co --version
```

## Correction to 1.8.5b9

b9 shipped a warning in `co auth lark` saying this flow could not create an
application on some data-residency tenants, and told people to create it in the
Lark Developer Console by hand instead. Its release notes said the same under
"Known limits", and #1537 was closed on that basis.

That was wrong. The flow works. The warning is deleted, and #1537 is reopened
and retitled with the real cause.

**If you followed that advice**, nothing you did is broken — a Developer Console
application is a normal application, and `co env set … --from-console` remains
the right way to bring its credentials in. You just did not need to.

## What was actually wrong

`co auth lark` printed the URL the SDK gives it:

```
https://open.larksuite.com/page/launcher?user_code=…
```

That page is the wrong one. Its own JavaScript reads the code, deletes it from
the address bar deliberately, calls its ack endpoint, and on any failure renders
**"Link expired"** — for a code the registration endpoint reports as
`authorization_pending` in the same second.

`lark-cli` never meets this, because it never uses that URL. It discards the
server's `verification_uri_complete` and builds its own (MIT, `larksuite/cli`,
`internal/auth/app_registration.go`):

```go
verificationUriComplete := fmt.Sprintf("%s/page/cli?user_code=%s", ep.Open, userCode)
```

`/page/cli`, not `/page/launcher`. That is the whole difference. It was never
the tenant, the region, or the code's lifetime.

## What this release changes

**The printed link points at `/page/cli`,** on the host matching the brand you
asked for. The URL is rewritten rather than rebuilt from scratch, because the
query carries the app preset that pre-fills the creation form; lark-cli has no
preset to lose and can rebuild.

**The `domain` override added in b8 is gone.** The registration protocol
bootstraps on the Feishu accounts host whichever brand you ask for, and lark-cli
leaves it there on purpose — brand selects the *verification host*, not where the
protocol begins, and polling follows the scanner's tenant by itself. b8's aim, a
Lark user not being handed an `open.feishu.cn` link, is now met by the link
itself.

**`--app-id` reuse works.** b9's notes claimed it "goes through the same page and
fails the same way". It was only ever tested against the launcher, so that claim
was never about `/page/cli`. Retested on 2026-09-15: it shows the existing
application with its settings and a Confirm button, and completes.

## Verified end to end

On the tenant b9 said could not do this, 15 September 2026:

| step | result |
|---|---|
| `/page/launcher?user_code=…` | "Link expired", while the poll answered `authorization_pending` at 11:28:43 |
| `/page/cli?user_code=…` | "Create your Lark app for CLI" — the working form |
| Create | "App created" |
| poll, 11:36:01 | `client_id`, a 32-character `client_secret`, `tenant_brand: lark` |
| `co env set … --from-console --secret` → `co env get` | both round-trip exactly |
| `co auth lark --app-id <id>` (the real command) | `✓ LARK application … saved`, exit 0 |
| `co lark check` | `✓ lark reachable` |

That fifth row is also the first time b9's encrypted store has been exercised
with a real credential rather than a test string.

## Known limits

The no-loss-across-a-reconnect gate in #1462 has not passed, which is why stable
is still 1.8.4. The application it needs now exists and its credentials are in
place; the run itself still needs a person to put the bot in a group and post to
it.

A chat message can command the agent and there is no sender allowlist until 1.9.
A browser that exits on its own takes the tab registry with it (#1513, targeted
1.8.6).

Retrieval of a stored secret is plaintext by design: `co env get` is the
substitution form, and `co env show` is the browsing command that redacts.
