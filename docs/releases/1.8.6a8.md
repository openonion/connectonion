# ConnectOnion 1.8.6a8

**Preview.** `pip install --pre connectonion` — a plain `pip install` stays on
stable 1.8.5.

You can take back what the bot said, and it stops looking machine-generated.

## A wrong answer in a group used to be permanent

The only repair was a second message. The wrong one stayed above it forever,
where the next person to scroll finds it first.

```
$ ID=$(co whatsapp send oc_ops "deploy finished at **14:02**")
$ co whatsapp edit "$ID" "deploy finished at **14:20**"
$ co whatsapp delete "$ID"
```

Both take the id `send` and `reply` already print, and find the chat from
`sent.jsonl`, so the id is the only string a caller has to keep.

**`edit` is yours only.** WhatsApp stamps an edit as coming from you and the
server checks it. Asking to edit a message you *received* says "no record of
sending" rather than "no such message" — the id is usually right and the
assumption is what is wrong.

**`delete` reaches further.** Your own message always; another member's when
this account is an admin of that group. WhatsApp decides that, and gives its
own reason when it refuses.

**WhatsApp only, for now.** `co feishu edit` and `co lark edit` name the
endpoints that exist for it and say nobody has wired them up. That tenant's API
quota is exhausted until 1 October, so shipping those calls would mean shipping
something never once run.

## Markdown, because a model writes Markdown

`**ready**` was arriving on people's phones with the asterisks still attached.
`send`, `reply` and `edit` now read their text as Markdown and translate it
into WhatsApp's own marks:

| written | received |
|---|---|
| `**ready**` | *ready* in bold |
| `*maybe*` | _maybe_ in italic |
| `# Deploy failed` | *Deploy failed* in bold |
| `- one` | • one |
| `[the run](https://…)` | the run: https://… |

Nothing inside a fence or backticks is touched — a code block is literal, which
is the point of one. `--plain` sends the characters exactly as typed.

## Three defects, all found by use

Two of them in a7, after publishing it.

**`check` printed its next step twice.** The next-step table had a fixed tip
for `co <provider> check` while a7 gave the handler branch-dependent ones, and
the two stacked; the branch pointing at the log printed two *different* tips,
which is the fork the table's own comments warn about.
`test_every_command_has_a_next_step` asserts *at least* one, which is why it
stayed green through all of it.

**`check` exited 0 while saying nothing was arriving** — against its own
documented "exit 3 on a problem", so `co whatsapp check && …` ran the next step
on a dead listener. Any state but connected now exits 3. The exception is "it
has not said whether its socket is up": *I cannot tell* is not *it is broken*,
and stopping on it would stop on a listener that is fine.

**`sent.jsonl` held the text that was typed, not the text that was sent.** Found
while verifying the translation on the real account. The record and the wire
disagreed, so `log` showed a message nobody in the chat had ever seen — this
release's own failure, one layer down, introduced by putting the conversion
inside `send`. Rendering moved to the caller; the rendered string is now both.

## Verified on the linked account

Not only in the suite. On the real number, against a real group: three messages
deleted for everyone (WhatsApp returned a revocation id for each, and the
listener logged all three), one message sent with bold, italic, strikethrough,
a heading, bullets and a link and read back byte-for-byte as recorded, and that
message then edited in place — one bubble, no second message.

Offline suite on this commit: 10,421 passed, 20 skipped, 2 errors — the two
being `test_native_egress_preflight_real_driver.py`'s network-policy errors,
which are present on main as well.

## Where 1.8.6 stands

Still preview. Every defect above was found by somebody using the software, and
two of them were in a build that had passed everything an hour earlier. That is
the argument for runtime rather than another checklist: let a build sit on a
real account before calling it stable.
