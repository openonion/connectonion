# ConnectOnion 1.9.7rc9 (release candidate)

Stable is **1.9.6**. Python **3.11+**.

- **`co discord` as your own account (experimental, opt-in)** (#3321): `co discord link --yes` links your Discord
  account by scanning a QR code with the phone app (or `--token`), and `listen` / `receive` / `reply` then work on
  your direct messages and group DMs as they do for WhatsApp. Replies show typing, pause like a person and are rate
  capped; co never opens a new DM, sends a friend request, joins a server or posts outside an allowlist, and it stops
  without logging in again if Discord limits the account. Automating a user account is against Discord's terms:
  link a throwaway account first. Not yet run against a real account. Bot mode is unchanged.
- **`co browser` falls back to system Chrome without closing other sessions' tabs** (#3315): when the paid engine
  cannot start and no paid browser is running, `--engine system` re-pins the daemon instead of requiring
  `co browser close`. With onionwright 0.0.17, a cached paid runtime that fails verification on every attempt is
  set aside and rebuilt (#3294).
- **Bare `co host` in an unserved project exits 1 and says how to serve** (#3297): since 1.9.7 a bare `co host`
  only shows status, so a script or logon task written for older versions stopped serving silently.
- **`co call` names the address it signed with** (#3298, #3182): inside a project with its own key it says so, every
  refusal names the address and key, and `--global` / `--co-dir` choose the identity.
