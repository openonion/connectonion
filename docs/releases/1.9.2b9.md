Stable remains 1.9.1. Install this opt-in beta by exact pin:

```bash
python -m pip install --upgrade 'connectonion==1.9.2b9'
```

## Use the connectors Codex already has

`co mcp` (Experimental) calls the MCP servers and account connectors you
already enabled in Codex (Gmail, Google Calendar, GitHub, Vercel, your own
servers) from the terminal. It needs no second login and runs no model turn.

```bash
co mcp ls                                   # servers, tool counts, auth state
co mcp tools codex_apps                     # one line per tool; read-only ones are marked
co mcp call codex_apps gmail.search_emails '{"query": "newer_than:7d"}'
```

- co starts `codex app-server`, opens an ephemeral session (no turn, nothing
  added to your Codex history), and uses `mcpServerStatus/list` and
  `mcpServer/tool/call`. Codex keeps every credential.
- A read-only tool runs at once and prints its own data as JSON. Any other
  tool (send, delete, create) prints what it would do and runs only with
  `--yes`.
- Claude Code's claude.ai connectors are not called. They are reachable only
  through a Claude turn; see [co mcp](../cli/mcp.md).

## Verification and limits

- Eight tests against a fake app-server, red before the module existed. The
  CLI gate suites pass (tips, next steps, cold-start import cost).
- Experimental because Codex marks its app-server protocol experimental; a
  Codex update can change it.
- Neither Codex nor Claude Code exposes Outlook on the measured machine.
- co rem does not use `co mcp` for mail yet (#2322).
