# ConnectOnion 1.9.3rc29 (release candidate)

Stable remains **1.9.2**; Python **3.11+** and the existing dependency floors are retained.

## Paid browser sessions on macOS renew past fifteen minutes

A paid WTF Browser session is prepaid fifteen minutes at a time, and the
runtime asks for the next period shortly before the current one runs out. On
macOS every renewal after an account's first was refused with
`idempotency_key_conflict`, so sessions ended at the first period boundary.

The macOS runtime sent its Swift interpolation `"renew:(state.sessionID):(sequence)"`
without the backslashes, so every renewal used the same key. Chromium
154.0.8037.100 carries the corrected runtime, and this candidate asks for it on
macOS (#2705). Linux renews through Onionwright, never had the bug, and stays on
154.0.8037.58.

Browsers already installed are also covered: the API now accepts the literal
key and stores it per session and period, so an older client renews too.

See the dev blog post *One key for every renewal*.

## Install after publication

```bash
python -m pip install --upgrade 'connectonion==1.9.3rc29'
```
