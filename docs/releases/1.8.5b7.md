# ConnectOnion 1.8.5b7 — beta

Beta, 14 September 2026. You can reach a tab the site opened for itself.

Stable stays **1.8.4**. This is not Latest and needs an explicit pin or
`--pre`:

```bash
python -m pip install --pre connectonion==1.8.5b7
co --version
```

## Change

**A page the site opens is a page you can work in.** A "view invoice" button, a
payment popup, any `<a target="_blank">` — the work moves to a new browser tab,
and until now the agent stayed behind. `tab ls` lists the sessions *we*
registered, so a page nobody registered appeared nowhere, and every `-t` command
kept running in the page it was already on.

```bash
co browser list_pages                  # every real page, and who is driving each
co browser -t mytask switch_page 1     # this session now drives page 1
co browser -t mytask get_text          # ...and every command after it
co browser -t mytask switch_page 0     # back
```

`tab ls` now counts the pages nobody is driving and names `list_pages`, because
the tab board is exactly where someone looks for a tab that is not there.

This is **not** the `use`/`switch` that 1.8 removed. That was a server-side
cursor deciding which *session* a bare command meant, and targeting stays per
command with `-t`. This chooses which *page* a session drives. Typing `switch`
now answers both, since the word names two different things and answering only
the deleted one sent people away from what they wanted.

A page another session is driving is refused by name. Extending what an agent can
reach is not a reason to weaken what keeps two agents apart.

## Also fixed, server side

The preview catalogue advertised a macOS Intel build whose bytes were never in
the bucket, with a digest that disagreed with the object now at that key. The
client verifies the signed checksum before executing anything, so a preview
caller on an Intel Mac saw a checksum mismatch — which is what a tampered
delivery path looks like. Removed in oo-api v0.1.18; preview now answers
`artifact_unavailable`, which is true. Production is unaffected: the verified
Intel build shipped in v0.1.17 and works.

## Known limits

Unchanged: the no-loss-across-a-reconnect gate in #1462 has not passed, which is
why stable is still 1.8.4 — that gate is the Feishu inbox, not the browser, and
nothing in this release moves it. A chat message can command the agent and there
is no sender allowlist until 1.9. A browser that exits on its own takes the tab
registry with it (#1513, targeted 1.8.6).

Page indexes come from `list_pages` and shift when pages open or close, so read
the list again rather than reusing a number from earlier in a task. Nothing
watches for new pages or switches automatically: a page appearing is not a reason
to go there, and that stays the agent's decision.
