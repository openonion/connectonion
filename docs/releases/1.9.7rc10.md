# ConnectOnion 1.9.7rc10 (release candidate)

Stable is **1.9.6**. Python **3.11+**.

- **Keys: one-click import that says what it is waiting for** (#3316, #3305, #3274): the Keys page leads with
  一键导入, whose sources are the buttons: Chrome, Edge, Brave, the macOS Keychain (one system prompt per item; a
  refusal stops the import and keeps what was filed), Apple Passwords (it cannot be read by other programs, so the
  button points to its CSV export), or a CSV file. While macOS asks to 允许, the page shows a waiting step with a
  spinner and 取消. A failure says why in plain words. The commonest one is a REM Host started outside your login
  session (by an upgrade or an agent), where macOS cannot show its prompt: the page then names the fix, `co rem open`
  from your own Terminal, and the Host moves into your session. Replies name sites only, never accounts or values.
- **Keys: co's own keys are listed** (#3305): the API keys co itself uses, from `~/.co/keys.env`, appear on the Keys
  page by name, with their values hidden.

Also in this candidate, from rc9: an upgrade no longer leaves the reader on the old build for 10–18 minutes. A build
that the upgrade broke mid-render is not counted as a failure of the new install, so the rebuild starts at once, and
the page says it is updating to the new version (#3310, #3295).

Known: a Host restarted by an upgrade or an agent still starts outside your login session until #3317 lands, so the
first Keychain import after an upgrade asks you to run `co rem open` from your Terminal once.
