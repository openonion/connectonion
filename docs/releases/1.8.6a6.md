# ConnectOnion 1.8.6a6

**Preview.** `pip install --pre connectonion` — a plain `pip install` stays on
stable 1.8.5.

Things that happen to the account stop being silence.

## A message arrived and nothing said so

The worst one was not on anybody's list.

Somebody sends this number a message. It arrives. WhatsApp hands the listener
the sender, the chat, the timestamp and a reason it could not be decrypted. We
had no handler for that event, so it was discarded — and **nothing anywhere
recorded that a message had existed.** Not an empty body. Not a row gated out of
the queue. Nothing.

The sender saw it delivered.

It was not on the list because nobody experiences it: the sender sees a sent
message, the recipient sees nothing, and there is no shared observation to
compare. A failure invisible from both ends is not reported from either. It
turned up only by printing what the SDK can tell us and reading the list.

```json
{"kind":"undecryptable","sender":"126121882435737@lid","sender_name":"aaronplus1996",
 "text":"could not be decrypted (SHOW)","mentioned":false,"at":"…"}
```

## Recording and waking are different questions

The owner decided these are all inbox events. What was left was whether each one
interrupts somebody.

| `kind` | wakes a consumer | why |
|---|---|---|
| `edit` | like any message | a correction is a message |
| `reaction` | never | including the bot's own 👀 coming back over the socket |
| `undecryptable` | direct only | nothing in a group event says it was for us |
| `joined` | **yes** | nobody else was added; the bot's first sight of a room |
| `group-info` | never | a rename is background |

Everything is recorded, because `--context` reads the record back and *"he
deleted that"* is part of what was said. Collapsing the two questions is the
same mistake `mention_only` was making when it decided what the bot was allowed
to **know** under a name about when it **speaks**.

`edit` arrives as a whole message with a flag on the envelope rather than as its
own event — a consumer reading it as new text answers a correction as though it
were a fresh question.

## No new fields

The record has changed shape three times in three releases — `kind`, `quoted`,
`sender_name` — and each costs every consumer a re-read. It stays at ten here.

Forwarded and view-once are *flags*, not kinds: a forwarded image is still an
image. They need an eleventh field, and that decision is written down rather
than spent in the same week.
