# ConnectOnion 1.9.3rc23 candidate: configurable ASR

Candidate under review, not a publication receipt. Stable stays 1.9.2.

`co asr recording.m4a` and `from connectonion import asr` expose one generic
audio-to-text capability. Codex is the default provider; save
`co env set ASR_PROVIDER connectonion` to use ConnectOnion's existing cloud
transcription, or override one call with `--provider`.

The Codex adapter is Python, with no codex-asr executable or Rust installation.
It reads the existing file-backed ChatGPT login locally and uploads the selected
audio to the unofficial Codex Desktop transcription endpoint. It never forwards
that login to OpenOnion or silently switches providers. Both choices are cloud
processing, not offline recognition or a promise of free subscription usage.

Twenty-six focused synthetic cases cover request construction, provider routing,
malformed authentication, HTTP errors/redirects, malformed responses, cloud
failure redaction and CLI JSON. A separately synthesized short English sentence
was submitted through the real Codex endpoint and transcribed correctly on the
owner's Mac. No personal recording was used. This single success does not
establish Chinese/mixed-language accuracy, long-meeting completeness, quota or
account compatibility. Full package/CI/release acceptance is recorded separately.

No timestamps, speaker labels, automatic conversion or long-audio segmentation
in this candidate. Original recordings remain unchanged; callers choose whether
to save transcripts or send them to memory. Existing `transcribe()` behavior is
preserved. See [ASR configuration and recovery](../asr.md).
