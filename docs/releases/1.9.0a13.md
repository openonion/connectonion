# 1.9.0a13 — REM's map-only Skill stays map-only

This opt-in preview corrects the bundled `rem-init` Skill. Its instructions said
the first pass did not start a model, but gave `co rem init --days 90`. In an
interactive terminal that command also investigates the owner's page and recent
People and projects. The Skill now passes `--no-investigate` explicitly and
leaves individual investigation until after the map is reviewed. Plain
`co rem init` keeps its documented interactive first-run behavior.

The published 1.9.0a12 package was exercised in a fresh private notebook on two
connected mailboxes. A seven-day run saved all 359 listed mail bodies. The
default 90-day map took 8.5 minutes, listed 3,196 messages, and saved 2,837
new bodies while reusing the 359 from the shorter run, with zero failures.
Three capped mail windows were split until enumeration completed. The resulting
notebook held 70 People, 18 organizations, 13 projects, and 150 Skill pages;
private files and directories had owner-only permissions. The relevant REM map,
mail, archive, first-run, and CLI tests passed: 235 tests. The model investigation
path was not run in this acceptance pass.

## Install

```sh
python -m pip install --upgrade 'connectonion==1.9.0a13'
co rem init --no-investigate
```

For the full interactive first run, run `co rem init` without the flag. It also
investigates pages with the configured model, subject to the CLI's stated caps.

## Known limits

The REM reader remains a read-only snapshot. It cannot yet compare claims before
and after a pass (#2096), save recall feedback (#2097), or answer questions
inside the reader (#2071). See the [a12 notes](1.9.0a12.md) for the prior
Windows snapshot fix.
