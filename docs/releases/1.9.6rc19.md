# ConnectOnion 1.9.6rc19 (release candidate)

Stable remains **1.9.5**. Python **3.11+**.

## Files between agents

- **`co send <address> <file or folder>`.** Sends files to another agent's running Host. They
  arrive byte for byte and are listed only once their size and sha256 match what was offered.
  `co receive` on the receiving machine lists what arrived, with who sent it. Files land in
  `.co/inbox/files/<date>/`, and nothing there is overwritten: a second `take.mov` becomes
  `take-1.mov`, and a folder sent after a file of the same name lands as one folder, `a-1/`.
- **An interrupted send continues.** The receiver keeps what arrived, under the file's sha256.
  Running the same command again picks up from that point. Retries happen by themselves; Ctrl-C
  stops the send (exit 130) and says how to continue. Measured on a laptop sending 5 GiB to a
  mini PC on the office network: stopped at 1.2 GB, the second run began at 1.2 GB, and the
  sha256 matched on both machines.
- **Who may send.** A contact, a whitelisted address or an admin of the receiver, on a direct
  signed connection. Anyone else is refused, on a `trust: open` agent too.
- **Never through the relay.** If only the relay reaches the receiver, the send stops and says
  so. For now, sender and receiver must share a network, or the receiver needs a public address
  (`AGENT_PUBLIC_DOMAIN`). Reaching an agent behind NAT is #3077.
- **The receiver's disk is protected.** An offer that would leave less than 1 GB free is
  refused, counting the room other sends still need. Partial files no one has resumed for a
  week are cleared.
- Speed is limited by the link: 8–14 MB/s over Wi-Fi, where raw TCP on the same link measured
  11.4 MB/s.

## Every sealed connection

- **No compression on sealed client sockets.** Sealed frames are ciphertext and do not
  compress. Profiling `co send` showed deflate taking half the time per megabyte for no
  saving; `co call`, chat and Remote Browser stop paying for it too.

See [docs/cli/send.md](../cli/send.md) and #3080.
