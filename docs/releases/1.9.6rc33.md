# ConnectOnion 1.9.6rc33 (release candidate)

Stable remains **1.9.5**. Python **3.11+**. macOS only for this feature.

## Read your own WeChat for Mac history, locally

`co wechat` reads **your own** WeChat for Mac chat history on your own machine.
Read-only and local: it never writes to WeChat's files, never touches its network
protocol, and nothing leaves the machine.

- **`co wechat doctor`** checks the prerequisites — macOS, access to WeChat's
  container, and whether a database key is saved — and names the exact missing
  step. The container probe is time-bounded, so a pending macOS privacy prompt
  cannot hang the command.
- **`co wechat key`** explains how to obtain the SQLCipher key as a consented,
  local step (a re-signed *copy* of WeChat plus Apple's own debugger — never the
  real app, no SIP change, no package installed). **`co wechat key set x'<hex>'`**
  saves a key you obtained to `~/.co/keys.env` at `0600`.
- **`co wechat chats`** decrypts each database in memory and lists its tables with
  row counts, revealing the schema rather than guessing it.
- **`co wechat decrypt --out DIR`** writes plaintext SQLite copies you can open
  with any sqlite tool.
- **`co wechat export --db D --table T --format json|md`** exports one table.

The SQLCipher-4 decryption engine adds **no new dependency** (`cryptography` is
already present) and is tested against an independent `sqlcipher`-CLI oracle: a
different implementation encrypts a fixture, ours decrypts it, and plain `sqlite3`
reads it back. Obtaining the key stays a consented manual step; WeChat 4.1.15's
own table schema is revealed by `co wechat chats` rather than assumed. Chat-aware
formatting (quotes, media, voice via `co asr`, sender names) and REM admission are
the next steps (#3146). Full design in `docs/wechat-read.md`.
