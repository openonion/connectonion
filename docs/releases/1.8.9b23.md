# 1.8.9b23 — Audit short item references

An opt-in preview on the 1.8.9 fix line
([#1722](https://github.com/openonion/connectonion/issues/1722)). Stable is
1.8.8.

The OneNote commands introduced numbered section and page lists in b21, but
`co audit --review` did not ask whether users can select a listed item without
copying its full name or provider ID. Its optional model review now asks that
question, and reports `short_reference` when the help page omits one
([#1927](https://github.com/openonion/connectonion/issues/1927),
[#1928](https://github.com/openonion/connectonion/pull/1928)). Commands that do
not act on listed items pass this criterion. The deterministic CLI checks are
unchanged, and a model verdict does not prove that a displayed number resolves
to the correct item; the OneNote terminal journey tests cover that behavior.

This preview also includes b22's fix for `co audit` on user-installed CLIs.
The b21 OneNote journey remains:

```bash
co onenote ls
co onenote pages 2
co onenote read 1
co audit co onenote
```

The first three commands were verified read-only against the connected
Microsoft account with b22. The five-page deterministic OneNote audit passed
after the user-site import fix. A focused regression confirms that the optional
review reports a missing short reference. No OneNote page was created by these
checks.

## Install

```bash
python -m pip install --upgrade 'connectonion==1.8.9b23'
co --version
```

## Scope

The model review gains one conditional question; help formatting, OneNote
numbering, account scope, and write confirmation do not change.
