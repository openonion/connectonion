# ConnectOnion 1.9.6rc17 (release candidate)

Stable remains **1.9.5**. Python **3.11+**.

## REM background

- **A folder REM cannot read no longer stops the night.** REM takes folder paths out of coding
  sessions and asks whether each is a repository. One session named a system folder only root may
  read; the check raised a permission error and every scheduled round after it failed while being
  prepared. An unreadable folder is now simply not a repository, at every place REM asks (#3066).
- **A round that could not be prepared is recorded as failed.** Those turns were saved as
  `completed`, exit 0, so the night's numbers showed 33 turns and no work with no reason given.
  The turn now keeps the error and its traceback, `co rem status` says how many turns in a row
  failed and since when, and Today says it too.
- **The message names the real cause.** An unreadable outside folder is no longer reported as
  "Cannot read or write the selected co rem files".
- **One deleted mail or attachment no longer stops scheduled preparation (#3073).** Gmail and
  Outlook HTTP 404/410 reads record the missing evidence ID and park the page or nightly item
  with a reason, then `next` moves on. An unchanged page stays parked until its text changes;
  a missing cited original is not fetched repeatedly. Other mailbox read errors remain failures
  with their messages. If every candidate is parked and no task was served, the turn reports
  failure instead of completion.

Turns that failed before this release stay recorded as completed; the count starts with the first
turn after upgrading.

## Upgrade

```bash
uv tool install --force 'connectonion==1.9.6rc17' --with onionwright --prerelease allow
```
