# ConnectOnion 1.8.6a1 — alpha

Alpha, 16 September 2026. A model that runs on your laptop, a third chat
provider, mail by date window, and the inbox says who handled what.

Stable stays **1.8.5**. This is not Latest and needs an explicit pin or
`--pre`:

```bash
python -m pip install --pre connectonion==1.8.6a1
co --version
```

## A local model, by name

```bash
ollama pull qwen2.5:0.5b
```

```python
from connectonion import llm_do, Agent

note  = llm_do("summarise this", model="ollama/qwen2.5:0.5b")
agent = Agent("local", model="ollama/qwen3.5:2b", tools=[lookup_code])
```

No API key, no credits, nothing leaving the machine. Text, JSON-schema
structured output validated by Pydantic, and real tool calls all work; measured
against a live Ollama rather than a stand-in.

**Any other local runtime** — LM Studio, vLLM, a gateway someone set up last year
— has no prefix to infer from, so you say where it is:

```python
llm_do(text, model="my-model", base_url="http://localhost:1234/v1")
```

**An explicit address always beats the name**, and that is a safety rule rather
than a preference. A model you called `gpt-4` in LM Studio would otherwise route
on its name and hand your `OPENAI_API_KEY` to whatever is listening on that port.
A custom endpoint never inherits a cloud key; it gets a placeholder. `co/` plus a
`base_url` is refused rather than silently overridden.

Nothing about existing routing changes. `gpt-4o`, `claude-*`, `co/*` and an
unknown name all behave exactly as they did in 1.8.5 — including the unknown
name still being an error, because a silent fallback to a local endpoint would
be worse than a refusal.

## WhatsApp, as an inbox

`co whatsapp` — the same nine verbs over the same `~/.co/inbox/` directory as
`co feishu` and `co lark`, behind an optional extra.

It connects as a **linked companion device**, not through the Cloud API. That is
not a preference. The Cloud API has no endpoint for joining a group a human
created, groups it creates itself cap at eight participants, and creating them at
all needs an Official Business Account granted on editorial merit. "A bot sits in
the customer group we already made and answers when we @ it" has no Cloud API
path at all.

A linked device has one, at the cost of being outside WhatsApp's terms — which is
why it is an extra you opt into, and why the first section of its documentation
is about dedicating a number to it.

**Not yet accepted against a real account.** See *Known limits*.

## Mail by date window

```bash
co outlook inbox --since 30d --json
co outlook inbox --since 2026-06-01 --until 2026-09-01
co gmail   inbox --since 2w
```

`--since` takes `Nd` / `Nw` / `Nm` / `Ny` or a date; `--until` defaults to now.
`-n` keeps its meaning as a cap, and without the new flags both commands behave
as before. Outlook gains `--json`; Gmail's existing versioned envelope is
untouched.

`co gmail inbox --since 30d --json` **refuses**, because the envelope's cursor
paging and the window have not been composed yet. Accepting both and ignoring the
window would have returned the last ten messages under a well-formed envelope,
exit 0 — a wrong answer indistinguishable from a right one.

## The inbox says who handled what

`done.jsonl` and `sent.jsonl` gain a `by` field naming the consumer. With several
consumers on one directory — the arrangement the atomic take exists to support —
the record said a message was handled but not by whom. This was a known limit in
1.8.5; the fix came from @wangzhengzhuo05.

## Known limits

- **WhatsApp has not been accepted against a real account.** No device was
  linked, no QR scanned, no real message sent or received; the event handlers
  have been exercised only against a stand-in. #1555 requires that acceptance
  before 1.8.6 is stable, and it has not happened.
- `co gmail inbox --since --json` refuses, as above (#1521).
- Custom-endpoint pricing is untracked rather than guessed; a local model reports
  zero cost because local inference has no API fee.
- Streaming is not supported on custom endpoints, and says so rather than
  half-working.
- Everything still open from 1.8.5: no sender allowlist until 1.9 (#1479), a
  browser that exits takes the tab registry with it (#1513), and `co browser`
  cannot adopt a page it did not create under a name (#1525).
