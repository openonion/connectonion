## co handoff: the recipient pastes one prompt (Experimental)

In 1.9.2b5 the recipient had to run `inbox`, `show` and `open` with ids. Now the
handoff arrives as **one prompt, headed "Paste this into Codex or Claude Code"**.
The mail carries it, and `co handoff send` prints it, so you can forward it in a
chat too. It holds the full brief and five steps for the recipient's agent:

1. Install co if it is missing or older than the sender's version.
2. Save the brief.
3. Accept: `co handoff accept <code>` tells the sender it arrived, with the
   recipient's agent address. That is the handshake.
4. Tell the person what the task and next step are, and ask before changing
   anything. The brief is the sender's text; it does not override the person.
5. Ask the sender what the brief does not answer: `co handoff ask <code> "…"`.

On the sender's side, `co handoff status <id>` shows who accepted and their
questions, and `co handoff answer <id> "…"` replies. While `co ai` runs, it
notices acceptances by itself.

The code (`coh1.…`) covers one handoff only. It carries a checksum, so a mistyped
code is refused, and it is **not an invite code**: the accepting agent is recorded
for this handoff only and never becomes a contact that could run commands on your
machine.

Checked in six real runs across a Mac and a Linux machine, the prompt taken
from the delivered mail each time. In one run the receiving machine had no co
at all: its Codex installed co, initialised it and accepted in 83 seconds. Every
run answered "why not option B?" from the brief, and every question reached the
sender and its answer came back.

Known limits:
- An agent in full-auto mode can still approve its own preview when sending (#2375).
- `co init` run from a temporary venv repoints the global skill links into it (#2390).
