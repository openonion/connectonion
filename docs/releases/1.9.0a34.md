# ConnectOnion 1.9.0a34 (preview)

## Install this preview

Stable remains 1.8.10. Install this opt-in preview by exact pin, then follow
the [first-run guide](https://docs.connectonion.com/rem#start):

```bash
python -m pip install --upgrade 'connectonion==1.9.0a34'
```

## Faster follow-up investigations

`co rem investigate PAGE` now saves the typed coding-session messages it
already parsed, with per-file read progress, in the notebook's owner-only
`.state/session-windows/` directory. Later CLI runs list the local sources,
read changed files and filter the saved messages to the page's requested time
window. A newly appended input or new session file is available on the next
run; unchanged transcripts are not parsed again. Source IDs stay tied to the
original session and byte offset. Deleting the directory rebuilds the derived
window. See [#2240](https://github.com/openonion/connectonion/issues/2240).

On one private 90-day notebook, a source-only pass found 2,050 Codex and
2,907 Claude Code typed messages in 103.5 seconds. The same pass in a new
process found the same counts in 2.1 seconds. These timings exclude mailbox
reads, model writing, page validation and reader generation. A synthetic
source test also checked appended input, a newly added session file, removal
of a session file and stable source IDs. The parsed window holds typed text,
not whole tool-output transcripts, and is not included in reader exports.

## Trial limits

This round measured source collection and rendered a read-only notebook
snapshot; it did not spend model tokens or complete the remaining first-run
pages. The 90-day cohort still has 255 unfinished investigations. The full
cohort and its page claims have not passed an all-page review.
