# ConnectOnion 1.9.3rc18 (preview)

Stable remains 1.9.2. Python 3.11+ is required; dependency floors are unchanged.

## Several mailbox aliases and domains on one account

The cloud already supports multiple owned addresses, but the CLI only listed
addresses and selected senders. It could not provision another address on a
chosen hosted domain. This preview connects that missing setup path:

```bash
co email domains
co email setup iron.share --domain mail.openonion.ai
co email setup iron.share --domain mail.openonion.ai --buy
co email addresses
co email default iron.share@mail.openonion.ai
co email inbox --address iron.share@mail.openonion.ai
```

Domain choices and the current price come from the configured backend. Repeat
setup with another domain listed by `co email domains` to hold the alias on both. Setup
without `--buy` never charges; buying adds an address without replacing the
account's other mailboxes or raising its quota. An address the account already
owns is not bought again. Availability is checked by the cloud when buying;
conflicts retain the backend's suggestions of other domains.

`co email send --from` and Python `send_email(from_address=...)` use the same
cloud ownership checks. The default sender follows the account across machines
and cloud deployments. People and AI agents use the same account model.

## Previously merged maintenance

Tool error hints now recognize presentation arguments the model supplied before
execution removes them. A supplied summary is no longer reported as missing;
injected runtime arguments remain excluded (#2652).

## Verification and limits

Email regression coverage includes setup, no-purchase previews, duplicate
ownership, domain errors, send-as, default selection, inbox filtering, sharing,
and existing email tools. DNS provisioning and actual inbound routing are
separate operational checks; registering a domain in the API is not proof it
can receive mail. See [the domain deployment record](../acceptance/email-domains-2026-10-23.md).

No email was sent and no mailbox was purchased on the owner's account for these
package tests. Arbitrary external domains such as mail.com are not claimable
with `co email setup`.
