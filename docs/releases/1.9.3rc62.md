# ConnectOnion 1.9.3rc62 (release candidate)

Stable remains **1.9.2**; Python **3.11+** and the existing dependency floors are retained.

## REM keeps reading, all night

- **New mail reaches a long round.** Mail used to be read only when a scheduled round began, so a
  round that ran all day left every mailbox unread since morning. Each new slot now reads the next
  mailbox into the running round, ahead of its remaining jobs.
- **The night is covered.** The default schedule adds 22:00–02:00 and 05:00. The old six slots, with
  three hours of follow-ups each, left 22:00–03:00 with nothing running. Notebooks still on the old
  default take the new one; times you set yourself are kept. The weekly Codex budget, not the number
  of slots, still bounds what the night spends. Run `co rem start` once to install the new wake times.
- **Thirty drafts a night.** A notebook still on the old cap of 10 takes the default of 30.
- **Replies to people you trust can go without you.** `- Direct send: partner|close` on a person's page
  lets REM send a reply its writer marks as ready, through the same 10-minute hold and Undo, recorded
  as REM's decision. The writer can only lower that permission, never raise it.

## Today, and pages as records

- **Today as a front page**: who is waiting on the left; on the right, what REM did overnight: replies
  drafted, tasks prepared, items needing no reply, items already handled, and who it could not draft
  for. A card with a draft shows REM's summary in your language.
- **People, Organisations and Projects lists are records**: no to-do headline or green button; one
  quiet link to Today. All records sits at the end of the sidebar.
- **Organisation page**: the name and summary lead the first screen; each role sits under its person.
- **One typeface** across the reader.

## Projects: timeline, list and board

- A **timeline** of real session ticks grouped by health, with REM's coverage row, a red line only for
  an overdue promise, a dashed forecast right of today, and at most five margin notes. One REM
  sentence leads the page and changes with the week / month / quarter / year zoom.
- A **list** (health, last cited, open promises, what is on file) and a **board** whose axis is a
  question: by health, who waits on whom, what could be put down, what may be the same project.
- Projects with a GitHub repository read their issues, pull requests, CI runs, releases and tags
  read-only through `gh`, within a per-round budget, cached under `.state/code/`.

## Knowledge graph and topics

- A **graph** of your records: kind by shape, search to focus, one or two hops, the rest dimmed. Person,
  organisation and project pages get a small local graph.
- **Topic pages** as records: the people, organisations and projects that mention a subject, each with
  the cited sentence, and a timeline. Run `co rem backfill topics --propose` once to file the subjects
  REM already holds evidence about.

## Morning message (off until you choose a channel)

- `co rem morning --dry-run` shows the one short message REM would send after the night: what it did,
  and the decisions that need one click. It sends only between 06:00 and 11:00, once a day, and only
  after `co rem config set notify.channel <telegram|lark|whatsapp|email>` and `notify.target`.

## Owed work: recorded, sealed, and held in this version

- An owed piece of work you approve is recorded with REM's prompt; **this version does not run it**.
  The card says so and offers the prompt to copy. The sealed runner (no network, no credential reads,
  no user rules, no MCP or plugins, its own folder) is in place for the next candidate, where it will
  run once its last boundary is proven.

## Tests

- A unit run fails when a test writes the real `~/.co`; changes by other processes only warn.
- Per-server SSH keys resolve in the current home, so tests no longer write them into the real one.
