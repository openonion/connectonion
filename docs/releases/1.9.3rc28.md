# ConnectOnion 1.9.3rc28 (release candidate)

Stable remains **1.9.2**; Python **3.11+** and the existing dependency floors are retained.

## One mailbox no longer stops the whole REM round

A REM sync reads its sources in turn. Before this candidate, the first source
that failed ended the round, and the rotation never moved past it: one mailbox
with a bad queued message stopped every later sync. Now a failed source is
recorded and the round continues with the next one (#2706).

- A queued message the mailbox reports as deleted (HTTP 404) leaves the queue
  instead of failing every read. Dropped messages are counted per source in
  the run record, the sync summary and `co rem status`.
- Outlook reads request immutable message ids, so a queued message that is
  archived or moved by a rule keeps its id and is still read.
- `co rem status` names the mailbox, date and HTTP status of a failed read
  instead of showing a check mark. A mailbox that has simply not been reached
  says "not read since", not "failed".
- Failure records keep only the exception class and HTTP status; no provider
  response text is stored or shown, including from older run records.
- One failing source no longer stops mail-archive resume for the others.

## The native schedule opens Codex when it is closed

REM's schedule is a Codex desktop automation, which only fires while the Codex
desktop app is running. `co rem start` now also installs a small launchd job
that, at each saved time, opens Codex in the background if it is not already
running, and does nothing if it is (#2707). It never runs REM itself; Codex
remains the only executor. `co rem stop` removes it, including when the Codex
task was already deleted in Codex.

REM now reads the automation index Codex currently uses (`codex.db`, falling
back to `codex-dev.db`) and reports a missed slot in `co rem status`.

Existing native-schedule users get the wake job by running `co rem start` once
after upgrading; until then status says the wake job is not loaded.

## Dependencies

pyasn1 0.6.5 and pypdf 6.21.4 for published CVEs (#2708).

## Install after publication

```bash
python -m pip install --upgrade 'connectonion==1.9.3rc28'
```
