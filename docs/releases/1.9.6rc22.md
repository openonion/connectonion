# ConnectOnion 1.9.6rc22 (release candidate)

Stable remains **1.9.5**. Python **3.11+**.

## `co browser` enters long text without a clipboard

- **When the paste does not land, the text is inserted through CDP.** On 1.9.6rc21, headless
  Chrome on Windows driven over SSH never took the Ctrl+V. The fallback typed key by key: 920 of
  1,402 characters in 120 s before the CLI's timeout. Now the whole text goes in through one
  `Input.insertText` call, which needs no OS clipboard. Only a field that refuses that too is
  typed key by key. Measured in headless Chromium with the clipboard unavailable: 1,402
  characters in under 10 s, and the page's own input handler counted 1,402.
- **The result says how the text went in.** `keyboard_type` and `type_text_by_selector` add a
  line: `Entered by paste.`, `Entered by CDP insertText: the field did not take the paste.` or
  `Entered key by key.`
- **A typing timeout says the field is partly filled.** Clear it before retrying.

Not yet re-measured on the Windows box itself. See [docs/cli/browser.md](../cli/browser.md),
#2901 and #3109.
