# ConnectOnion 1.9.6rc21 (release candidate)

Stable remains **1.9.5**. Python **3.11+**.

## Files wait when the receiver cannot be reached

- **`co send` to an agent it cannot reach directly.** When the receiver's Host is behind a
  router or not running, a file of up to 10 MB waits on the server for 7 days instead of the
  send stopping. It is a NaCl box to the receiver, with the name and sha256 boxed separately,
  so the server holds neither a name nor a byte of the file.
- **`co receive` takes it.** The receiver opens the box with the sender's key, which proves who
  sent it, checks the sha256, lands it in `.co/inbox/files/<date>/` beside direct sends, and
  deletes it from the server. Files from someone who is not a contact, whitelisted or an admin
  stay waiting and are listed with their size and expiry; `co trust add` lets them in.
- Larger files still need a direct send. A box delivered twice lands once, and nothing in the
  inbox is overwritten. Measured end to end between a laptop and a mini PC: 2.9 MB and 1.9 MB
  arrived with matching sha256 on both machines; an 11.4 MB file was refused at the sender.

See [docs/cli/send.md](../cli/send.md) and #3088.

## `co browser` pastes

- **`keyboard_type` and `type_text_by_selector` paste the text as one event.** Typing Latin key
  by key took about 0.1 s a character: a 1,402-character post had 610 characters in when the
  CLI's 120 s timeout cut it off, and the truncated text was used. The paste holds the
  daemon-wide clipboard lock, checks the text landed, and restores the clipboard.
- A field that refuses the paste is typed key by key as before. `--human` (`human=True`) types
  key by key on purpose, for fields where cadence matters.

See [docs/cli/browser.md](../cli/browser.md) and #2901.
