# 1.8.9b7 — Claude Station can start in the browser

An opt-in preview on the 1.8.9 fix line. Stable remains 1.8.8.

## Fixed

- A new `co claude` Station can hand over to O Chat before anyone types in
  the terminal. The first browser prompt starts a new native Claude session;
  later prompts and a return to the terminal use the resulting session ID.
  Previously the Hook supplied an ID before Claude had written a resumable
  transcript, so the first browser turn failed on `--resume` (#1776).
- A Claude start failure before native initialization now sends the matching
  browser request a negative `PROVIDER_INPUT_ACK` immediately. The browser
  retains its draft instead of waiting for the ACK timeout.

The local O Chat development app was exercised in Chromium against a real
Haiku session starting with zero terminal prompts. The browser took control,
received a Write approval, wrote the requested file after Allow once, showed
the native reply, and returned control to the terminal. Desktop approval and
mobile completion screenshots were captured. The focused Core suite passed
124 tests. The 1.8.9b7 release workflow tests the package separately.

Browser evidence: [failure before fix](assets/v1.8.9b7/before-blank-session-desktop.png),
[first-turn approval](assets/v1.8.9b7/after-first-turn-approval-desktop.png),
and [completed mobile view](assets/v1.8.9b7/after-completed-mobile.png).

## Known limits

Station browser permissions remain intentionally narrow: verified workspace
file edits can be approved once; Bash, MCP tools, user questions and plan
changes are denied rather than presented as Happy-style approval choices.
The browser's improved native-start error wording requires the paired React
client release.
