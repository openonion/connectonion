# ConnectOnion 1.9.0a16 (preview)

This preview fixes two Gmail scan costs found during a real REM first run.
Gmail requests previously had no socket timeout, so an unresponsive HTTPS read
could leave init waiting indefinitely. They now time out after 30 seconds and
use the Google client's existing retry behavior.

REM splits a seven-day mail window when Gmail returns its 200-message cap. The
old path fetched metadata for all 200 messages before deciding to split, then
fetched those headers again in the smaller windows. The REM-specific listing
now keeps only IDs at the cap and fetches metadata after the split. Other Gmail
list commands retain their full results.

## Real-data verification

An isolated private 90-day init listed 1,284 Gmail and 1,918 Outlook messages.
It archived all 3,202 bodies without a failure and completed 37 model turns:
the owner's quick and full passes plus 19 people, 12 projects and 4 related
organizations. The 36 distinct selected pages all have a nonempty Sources
section and numbered citations. Those checks establish coverage and
traceability, not the truth of every model claim. No private message or page
text is included in this release.

The 327-message Gmail week that stalled the original trial completed in about
81 seconds with the fix. The owner page appeared after the full map and body
archive; making that first useful page arrive sooner remains an onboarding
improvement to measure separately.

The focused Gmail and REM command suite passed (224 tests). A broader local
unit and CLI run passed 14,189 tests with 21 failures outside the changed
Gmail scan path, including terminal styling and a docs version check. CI on
the exact release commit is the publication gate.
