# ConnectOnion 1.8.6

**Stable.** `pip install connectonion`.

WhatsApp as an inbox, on a number a person already uses — with an undo.

## Twelve verbs against a real number

`co whatsapp` links a device, sees the groups that number is already in, and
answers only where it was addressed:

```
$ co whatsapp check
✓ whatsapp configured · listener pid 83467 · 0 unread · ~/.co/inbox/whatsapp
✓ connected as 61410724095 since 2026-09-19T04:00:47Z
```

Nine verbs became twelve. The two that matter most were the last to arrive:

```
$ ID=$(co whatsapp send oc_ops "deploy finished at **14:02**")
$ co whatsapp edit "$ID" "deploy finished at **14:20**"
$ co whatsapp delete "$ID"
```

**`edit` and `delete` are what make a bot safe to put in somebody else's
group.** Before them, a wrong answer in front of a customer was permanent — the
only repair was a second message, leaving the first one above it forever. Both
take the id `send` and `reply` already print.

`edit` is your own messages only: WhatsApp stamps the edit as coming from you
and the server checks it. `delete` also covers another member's message when
the account is an admin of that group.

## Addressed, not merely present

A bot in a group sees everything and should answer almost none of it. A message
is for us when it `@`s us, **or when it quotes something we said** — a reply to
the bot is addressed to the bot, and that case has no `@` in it anywhere.

Non-message events are recorded rather than dropped: a message that arrives
undecryptable, being added to a group, a rename. The sender saw "delivered";
something on our side should be able to say it existed.

## Markdown arrives as formatting

The thing writing these messages is a model, and a model writes Markdown.
WhatsApp does not read Markdown, so `**ready**` was arriving with the asterisks
still attached.

| written | received |
|---|---|
| `**ready**` | *ready* in bold |
| `# Deploy failed` | *Deploy failed* in bold |
| `- one` | • one |
| `[the run](https://…)` | the run: https://… |

Fences and backtick spans are left literal. `--plain` opts out.

## Local models, and no quiet fallback

`ollama/…` does plain text, structured output and tool calling. Point the local
endpoint somewhere dead and it raises, naming the model and the server, with
hosted keys sitting unused in the environment. A local model that silently
becomes a paid one is worse than a local model that fails.

## Mail and calendar

Listings take `--since` and `--until`, and compose with `--json` instead of one
silently dropping the other. `co gmail inbox --since --json` keeps its envelope:
`status`, `complete`, `account`. Calendar invitations reach their attendees —
`sendUpdates` had never been passed, so an event with `--attendees` notified
nobody while the confirmation read the same either way.

## How this release was tested, and what that says

The offline suite is **10,431 tests**. It reported **none** of the twelve
defects fixed in this cycle.

Eleven of them were found by somebody using the software: `mentioned: false` on
a real mention; `✓ whatsapp reachable` derived from four facts that are not the
network; a `cancel` that reported deleting one message and deleted another;
`--since 30d` returning month-old mail; a listener that kept printing
`listening` after being unlinked; a message that arrived undecryptable and was
recorded nowhere; a log that showed a message nobody in the chat had ever seen;
and a `send` with no text that delivered an empty bubble and exited 0.

Two of those were found in a build published an hour earlier, which had passed
everything.

The gate for this release was #1555's requirement that WhatsApp be accepted
**against a real account** — not a mock. It closed on 19 September: a linked
number, real group traffic with the mention gating checked case by case, two
unattended reconnects, and the new verbs used to delete messages the bot had
already sent into a customer's group. The record is
[docs/acceptance/1.8.6/release-candidate-2026-09-19.md](../acceptance/1.8.6/release-candidate-2026-09-19.md),
written against the package installed from PyPI rather than a checkout.

Nine previews, 1.8.6a1 through a9, fed this release.

## Known limits

- **`edit` and `delete` are WhatsApp-only.** `co feishu edit` and `co lark edit`
  name the endpoints that exist for it (`PUT` and `DELETE` on
  `/im/v1/messages/<id>`) and say nobody has wired them up. That tenant's API
  quota is exhausted until 1 October, so implementing them would have meant
  shipping calls never once run.
- **No sender allowlist until 1.9** (#1479). A bot in a group answers anyone in
  that group who addresses it.
- **One connection per linked device.** WhatsApp allows a single socket, so
  `send` hands its text to the listener rather than opening a second one, and
  says so when no listener is running.
- **`chat_name` is not populated** (#1583): the group's subject needs an API
  call per group and is not kept in the local session.
- Environment sync (#1476) and browser profile import (#1477) are not in this
  line, per #1555.
