# ConnectOnion 1.9.3rc20 (preview)

Stable remains 1.9.2. Python 3.11+ is required; dependency floors are unchanged.

This preview fixes repeat setup for an already-owned email address when its
domain has closed to new purchases. The CLI now checks the cloud ownership list
first and reports `Already owned` without another purchase. New addresses still
require a currently enabled hosted domain and an explicit `--buy`.

## Multiple addresses, one account inbox

```bash
co email domains
co email setup my.agent --domain trustxmail.com
co email setup my.agent --domain trustxmail.com --buy
co email addresses
co email default my.agent@trustxmail.com
co email inbox
co email inbox --address my.agent@trustxmail.com
```

The setup preview shows the current price without charging. The cloud checks
availability when buying. Each owned address belongs to the same account's
inbox; `--address` narrows that inbox. Selecting a default sender does not split
received mail. CLI, Python tools and cloud deployments share the account's
ownership and default-sender rules.

## Verification and cloud scope

The new regression reproduces the closed-domain/owned-address failure before
the fix. All 115 email-related SDK/CLI tests pass after it. The tag release
workflow gates publication on the full offline matrix, dependency audit, CLI
audit and installed-package verification.

The deployed service currently offers mail.openonion.ai and trustxmail.com.
The latter's catch-all was migrated to Agent Mail with the owner's instruction,
and a provider test reached the mail store. The owner's primary-address
self-test also appeared in the authenticated inbox API. The CLI send attempt
itself hit its existing monthly quota; no quota upgrade or mailbox purchase was
used for those tests. steadmail.com and oakinbox.com still need incoming
routing enabled and accepted before they can be offered.

See [the current deployment acceptance record](../acceptance/email-domains-2026-10-23.md).
Package regression tests do not establish delivery for an unconfigured domain.
