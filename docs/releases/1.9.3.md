# ConnectOnion 1.9.3

## Install

```bash
python -m pip install --upgrade 'connectonion==1.9.3'
```

Python **3.11+** and the existing dependency floors are retained.

## REM does the work

- **Owed tasks run.** An approved task runs now, with full access, through ConnectOnion's own
  integrations: `co claude` (Claude Code, with your own Claude setup) or Codex.
- **Replies to people you trust can go without you.** REM sets a person's direct-send tier from the
  relationship (partner, close) and never touches a tier you set. Sends go through the 10-minute hold.
- **No count caps.** The night is bounded by the weekly Codex budget, not by numbers of drafts or
  turns. A task refused twice for the same reason is parked and retried another day.
- **Translation into the languages you write.** With no languages set, REM translates into the
  languages detected from your own writing, with a share of every night.
- **Four model levels.** Each stage runs on the model its difficulty needs: summaries on level 1,
  translation and extraction on level 2, investigation and drafting on level 3, deepening, audits
  and owed tasks on level 4. `models.level1`–`level4` and `route.<stage>` override.
- **A designed morning email** to your own mailbox (`notify.channel outlook`), in your language: what
  REM prepared and sent overnight, and at most three decisions, one per person.
- **Honest status.** A mailbox not read for a day shows when it was last read; nights are counted.
- **The night schedule** replaces an old pinned default once; `schedule.profile dense` is available.

## Hand any unfinished item to an agent

- **Every unfinished row, not only those prepared overnight.** Each row in Today and on all three
  bands of Waiting on you carries one line of actions: **Hand to Codex · Hand to Claude · Talk it
  over ▾** (交给 Codex · 交给 Claude · 聊一聊). Before, only the night's own listing could be handed
  off, so most buttons on a busy notebook answered "No pending item".
- **The row follows the work.** It reads "Codex is working · Stop · Undo", then "Codex finished ·
  See result · Undo"; See result opens the deliverable in place, and Undo brings the buttons back.
  Stop is confirmed.
- **Talk with Codex or Claude about an item.** Talk it over opens a real conversation in the page,
  seeded with the item, that resumes the agent's own session on every turn. On an agent-session
  page, **Continue with Codex** (or Claude) replaces the old command to copy, resuming the archived
  session in its own folder.
- **Agent replies render as safe Markdown**: headings, lists, code and links, never raw HTML.

## The reader

- **Opens at once.** `co rem open` serves the last rendered page from disk and rebuilds behind it.
  There is one stable link per notebook, so a reload shows the newest render; a new install
  re-renders the saved pages; a cold open waits for its own Host and says so.
- **Fuse design.** One ink, one paper, four sizes. People and organisations are records: the name at
  display size, a fuse from the first dated exchange to today, what they said in their own words,
  no to-do list. Today leads with what waits, red only past a real due date.
- **Today** hides counts and sections that are zero, and the run banner is in the reader's
  language. On a phone, Waiting on you puts the date under the title so the text keeps the full
  width. A page's translation status is a small mark.
- **The sidebar** has three groups with All records last; only Waiting on you has a count; the
  footer names the version ("co 1.9.3"). On a phone a Menu button opens it as a sheet. Activity and
  Reviews leave the sidebar and stay reachable.
- **Snapshots link to the live reader** on this computer instead of printing a command.
- **The reviews page answers in place**: yes, no or not sure, or an answer box, saved without
  leaving the page.

## Fixes

- `co rem open` works on Windows again.
- A section you opened stays open, and the scroll position stays, when the page redraws after a
  sync.
- The page and its details share one time, so they agree on a slow machine.
- Stop ends a running task reliably, and the run records that it was stopped.
- A Claude task loads your own Claude setup instead of a bare safe mode.
