# ConnectOnion 1.9.3rc45 (release candidate)

Stable remains **1.9.2**; Python **3.11+** and the existing dependency floors are retained.

## The native REM schedule survives a cold start (#2785)

- The launchd wake job opened Codex desktop with `open -g -j`. `-j` starts the app hidden, and a
  hidden Codex does not run its automations: the first cold start on a real notebook missed its
  17:00 slot while `co rem status` reported the app as open. The job now runs `open -g -a`, which
  keeps the window visible without bringing it to the front; showing the window fired the missed
  automation within a second.
- `co rem status` now says which case it sees: "Codex is open but did not run the HH:MM slot;
  show its window once, then run co rem start to reinstall the wake job", or the earlier "was the
  desktop app closed?" when the app is not running.
- **After upgrading from rc44 or earlier with the native schedule, run `co rem start` once** so the
  wake job is rewritten.

## A scheduled visit that stops at the daily cap is recorded (#2786)

- `co rem next --scheduled` that stops with "daily cap reached" leaves the same run record the
  child path leaves (`budget_exhausted`, "the day's runner calls are spent"), so `co rem logs`
  shows the slot was visited. Interactive `co rem next` at the cap still leaves nothing.

## Plainer `co rem` help (#2782)

- Fifteen `co rem` help pages were rewritten after `co audit co rem --review`: shorter sentences,
  effects named before options, no unexplained references. Hard-rule audit: 21 of 21 pages pass.

## Install after publication

```bash
python -m pip install --upgrade 'connectonion==1.9.3rc45'
```
