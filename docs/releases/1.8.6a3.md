# ConnectOnion 1.8.6a3

**Preview.** `pip install --pre connectonion` — a plain `pip install` stays on
stable 1.8.5.

A message says what it is, and what it answers.

## The record grew two fields

Everything here comes from one observation: a group message was arriving as text
and a boolean, and both were sometimes not enough to act on.

**`quoted` — what a reply is answering.** Somebody quotes the bot's own line and
writes "this one is wrong". The record used to be those four words with nothing
pointing at "this one": a consumer could not answer it, and could not tell it
had been asked.

```json
{"text":"这条不对","kind":"text",
 "quoted":{"id":"3EB0C796…","sender":"132754033377342@lid",
           "text":"收到：LID @提及现在能识别了","kind":"text","from_me":true},
 "mentioned":true}
```

`from_me` is the field that changes behaviour: **replying to the bot and
replying to somebody else in the same group are different events**, and a bot
that joins the second is the bot everyone mutes. `mentioned` reads that same
value rather than computing its own, so the record and the behaviour cannot
disagree.

All of it had been arriving in every reply since this provider's first version,
in the same struct the mention parser already reads. One field was taken out of
it and the rest was dropped.

**`kind` — what actually arrived.** An image, a sticker, a voice note and a
message with genuinely nothing in it all used to arrive with an empty `text` and
no way to tell them apart, so a consumer either answered noise or silently
dropped real messages. `text` for anything readable as words; otherwise the
platform's own word — `image`, `video`, `audio`, `document`, `sticker`,
`location`, `contact`, `reaction`. Captions ride along in `text`. A variant we
have never seen keeps the platform's own name, because WhatsApp has 107 of them
and adds more.

## Mail

**`co gmail inbox --since 30d --json` composes at last.** It used to refuse, on
the grounds that a window had to be reconciled with cursor paging and
completeness. It did not: the window narrows the query the envelope already
pages through, so the cursor stays bound to its query, `complete` still comes
from Gmail's page token, and the cap still means what it meant. Outlook had been
composing the same two flags all along, which is what made the refusal a gap
rather than a design.

## Verified

## Known, and not fixed here

- `co whatsapp listen` starts on a session that was logged out, prints
  `listening`, and receives nothing — so "nobody has messaged us" and "we have
  been logged out for a day" still look identical. `check` catches it; nobody
  runs a diagnostic when nothing appears to be wrong (#1581).
- `sender` is an opaque `…@lid` with no display name (#1583 item 4).
- Edits, revokes, forwards and group lifecycle events have no defined shape
  (#1583 item 5).
- A consumer is handed one message and no conversation around it (#1565).
