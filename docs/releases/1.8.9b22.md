# 1.8.9b22 — Audit a user-installed CLI

An opt-in maintenance preview on the 1.8.9 fix line
([#1722](https://github.com/openonion/connectonion/issues/1722)). Stable is
1.8.8.

The 1.8.9b21 OneNote commands work after a `pip --user` install, but
`co audit co onenote` could say that no OneNote page was reachable. The auditor
runs each help page with a fresh HOME to keep account files and configuration
out of the test. Python also uses HOME to locate user-installed packages, so
the `co` entrypoint failed to import `connectonion` before it could print help
([#1920](https://github.com/openonion/connectonion/issues/1920),
[#1921](https://github.com/openonion/connectonion/pull/1921)).

The audit now preserves the original Python user-package base while keeping
HOME and the working directory isolated. It also prevents bytecode writes.
This repairs the terminal check without changing OneNote data or credentials.

```bash
co audit co onenote
```

The installed b21 package reproduced the unreachable-page error. With the fix,
the auditor reached all five OneNote help pages and found no issues. The
numbered `co onenote ls` → `co onenote pages 2` → `co onenote read 1` journey
also succeeded against the connected account with the published b21 package;
no page was created during this check.

The focused audit/help checks passed (9 tests). The offline suite passed
12,911 tests with 35 skips when the three real Chromium egress preflight
tests were excluded: those independently reproduced two teardown errors from
this laptop's no-network test guard. The b22 wheel and source distribution
passed `twine check`, and 13 installed-wheel tests passed.

## Install after publication

```bash
python -m pip install --upgrade 'connectonion==1.8.9b22'
co --version
co audit co onenote
```

## Scope

This is an audit subprocess fix. The OneNote navigation, temporary row
numbers, `--listing` pinning and guarded create behavior from b21 are
unchanged.
