# ConnectOnion 1.9.0a40 (preview)

## Install this preview

Stable remains 1.8.10. Install this opt-in preview by exact pin, then open
your local REM reader:

```bash
python -m pip install --upgrade 'connectonion==1.9.0a40'
co rem open --local
```

## Read Skill usage without mistaking it for a verified run

The Skills list and Skill pages now call their session-derived number
**skill-name matches**. It counts invocation attempts matched by name in
coding sessions, across the observed window. The last date is labelled
**last name match**. This number cannot establish which installed copy or
version ran, or whether the task succeeded.

The separate `Run evidence` section now calls its number **retained evaluation
attempts**. It counts available eval records, so zero there can coexist with
several coding-session name matches. The one-line distinction appears beside
the count, before Full memory; the complete note and source remain visible.
This addresses [#2246](https://github.com/openonion/connectonion/issues/2246).

On a phone, Skills list names now have 44-pixel touch targets. A Skill that is
only mapped from metadata offers **Copy investigation command** in the lead
card, within the first screen, with the full command still shown below.

## Trial limits

An invented notebook was rendered in Chrome at 375×812 and 1440×900. The
sample had three coding-session name matches and zero retained eval attempts;
the review checked that the list, lead, Full memory and Usage panel described
these consistently. It also checked touch navigation, the mapped-page action,
source access on a written Skill, keyboard focus, privacy state and horizontal
overflow. The trial did not execute the Skill, inspect a user's private
account, or validate any remembered claim. Only the sampled pages and states
were visually reviewed.
