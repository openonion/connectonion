# Large-project source and experience review — 2026-10-03

Independent AI review from a technology-founder perspective with marketing and
UI experience. No human founder participation is claimed. Private input bodies,
repository paths and screenshots remain outside this repository.

## Source selection

The previous bounded pool excluded complete root README/manifests and selected
implementation mostly alphabetically. In a large Python project, this omitted
the declared CLI and REM implementation. Metadata prefixes stopped before the
product explanation and CLI declaration.

The candidate keeps the 60-file and 1 MB per-file limits, prioritizing complete
root descriptions/manifests, supported declared CLI targets, then literal
sent-input path/name hints. Implementation precedes supporting docs/tests among
hinted files; later mentions rank first. Hints guide discovery, not attribution.
The actual seven-input pool now includes the complete README and manifest,
declared CLI module and 24 REM source files. This is bounded source availability,
not evidence that the model reads every decisive clause.

Python target discovery currently supports ordinary unquoted `[project.scripts]`
declarations mapped to root package modules. It does not guarantee src layouts,
quoted keys, commented headers, Poetry declarations or every valid TOML shape.
The complete tracked tree distinguishes listed files from supplied bodies.
Excluded or omitted bodies do not establish missing implementation.

## Actual page correction

The actual framework page was manually corrected against eight retained
repository packets and 14 cited native user inputs. Fifteen baseline cited
inputs were read separately. Targeted integration files were additional manual
review reads; they were not all in the bounded pool selected from seven new
inputs. No model call, external service, installed CLI, publication or deployment
was executed in this correction.

- Slack search initializes both user and bot clients; bot-only access does not
  enable it. Channel history and search have different access requirements.
- Canny status/comment previews require an API key and an actor user ID, then
  read the post before the `--yes` mutation gate.
- Linear write previews resolve names or read issues before that gate; they
  require API access and are not offline dry runs.
- Direct Linear/Canny API paths are inspected source facts. A user request for
  MCP support and the README's planned MCP command do not establish complete
  feature or release state.
- Historical requests with missing outcomes no longer become current OPEN or
  Next exchanges cards. Two unsupported baseline attributions were removed.
