## Selected repair: don't undo a subject correction

The prior subject's dated field is copied into a candidate's Unknown solely because the file path is unchanged. A second restoration path can also fill fields from an extraction packet gathered for that prior subject. The repair detects a changed H1 subject title without a retained explicit routing anchor: the same unqualified Facts.Email (or legacy Contact.Email) address for people or an unqualified listed Domains value for organisations. Case-only title edits and ordinary email/domain-to-name first writes retain recovery. When continuity is missing, it skips old contact-date restoration and automatic extraction-pack refill, leaving candidate-provided facts intact. It does not decide that two names are the same person, merge entities, drop page content or auto-repair the real notebook.

Tradeoff: a legitimate rename/rebrand without a retained explicit routing anchor requires the writer to retain or reestablish its facts explicitly. A shared domain suffix, incidental mention or rejected/Unknown-qualified address/domain is not an anchor. Qualified values conservatively require the writer to supply its facts explicitly. The code cannot prove identity continuity from a shared file path. Shared explicit anchors preserve existing recovery; these anchors are routing continuity, not proof of person/legal-entity identity. Unchanged-title recovery remains supported. Same-title identity collisions and any already-written incorrect facts remain outside this repair. Independent review caught rejected addresses being mistaken for anchors; five additional red regressions covered rejection wording, annotated domains and legacy Contact continuity before the final fix.

Red evidence:4title-change contact-date cases failed, plus an actual candidate-promotion regression restored the previous contact date and source. After the fix, the page-review and fact-extraction suites pass **204 tests**. Ordinary date recovery, source-number remapping, candidate dates, case-only edits, first-write routing continuity, different addresses on one domain and incidental old-address mentions remain covered. Two additional boundary regressions failed before narrowing the first implementation to preserve ordinary anchored renames. The broader page-review, extraction, facts, runner, investigation and people-page suites pass **488 tests**. Independent AI source review found and resolved the rejected-anchor case and confirmed legacy first-write compatibility. These are source/data tests, not a real model or browser acceptance run.
