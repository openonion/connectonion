# Remaining session workspaces: source and experience review

This is candidate work in draft PR #2141, not a release. The independent reviewer
was an AI using a marketing/UI technology-founder perspective. No human founder
participation is claimed. Private identities, paths, original bodies and images
are omitted from this report.

## Scope and useful findings

Four ordinary mapped workspaces had retained task history but no established
software-product identity. We read all 48 retained native Desktop/voice inputs:
8, 10, 5 and 25 respectively. The independent reviewer matched all 48 complete
bodies, source identities, timestamps and input-scope limitations to canonical
archive records. A bounded local-file inventory found no eligible text in the
inspected pool; this does not establish that every folder has no files.

The four pages were manually written from that evidence. Their 32 cited inputs
(7, 9, 5 and 11) were independently checked for identity and Sydney date; all
four final page hashes matched the private audit. These citations are a subset
of the 48 inputs, not additional conversations.

| Workspace scope | Supported historical finding | Unverified outcome |
| --- | --- | --- |
| Engagement review | Update each person's memory/status between reviews. | Saved updates and completed engagement batches. |
| Workshop task history | Verify the recipient, use approved text, capture a screenshot, send once without retries. | A delivered message or completed later like request. |
| July workshop task history | Save-only login instructions were followed by a separate invocation; an engagement request asked to display content. | Successful login, social actions and event registration identity/link. |
| Voice-session workspace | Preserve client originals in a separate organised copy and leave client replies with the owner. Later Wiki navigation requests are a separate subject. | Actual permissions, deployed navigation, implementation or merge. |

Pasted skill definitions establish requested behavior, not installation, browser
properties or execution. Folder names do not establish product identity. The
writer instructions now describe this distinction and permit a session-workspace
opening when a software product is unknown. Automatic compliance is unproven.

## Observed defects, fixes and recheck

The initial rendered review found that tag priority selected later `Now` or
`Changed` lines over the first useful Insight. The reader now uses the first
Insight and recognises its `Pattern` prefix. Shorter first findings retain their
historical scope; unknown outcomes remain visible in context.

It also found that a local directory filled an explicitly unknown Repository.
The reader now respects explicit Unknown facts, keeps directory metadata under
Local path and uses that label in search when no repository is declared. All
four final Facts panels show only one of seven facts known: the cited last
retained-input date. Mapped session counts are not completed-run counts.

Two browser regressions reproduced these defects before the fixes and passed
afterward. Final actual desktop, tablet and phone views independently confirm
the first useful finding, Local path and unknown Repository. An ambiguous
request phrase was also changed to past request wording and source-checked.
