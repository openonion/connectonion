# ConnectOnion 1.8.0a5 WTFbrowser Preview Plan

Issue: [#1315](https://github.com/openonion/connectonion/issues/1315)

## Outcome

ConnectOnion 1.8.0a5 will exercise the paid WTFbrowser Chromium 151 stack through an
isolated preview control plane before this candidate can affect the production
catalogue. The preview must prove the real $0.025 session lifecycle with exact
cross-repository version and channel binding.

This work is rebased onto current `main`, including the reviewed 1.8 paid-path,
proxy, destination-policy, private-runtime, terminal-state, and installer-pin
hardening. It does not authorize a ConnectOnion package publication or
promotion of preview objects into production.

## Trust and release boundary

```text
ConnectOnion 1.8.0a5
  -> dedicated browser preview API origin
  -> signed manifest must say channel=preview
  -> exact Onionwright 0.0.13.dev5 with the pinned Playwright 1.61.0 API
  -> Onionwright runtime must say channel=preview
  -> preview Chromium 151 catalogue
  -> paid session create / renew / release
```

Any channel or exact-version mismatch fails before browser preparation and
before the billing boundary. `OO_API_URL` cannot redirect this preview path to
the ordinary backend. All authenticated traffic is fixed to
`browser-preview.oo.openonion.ai`, with no environment override. The release
HTTP session uses a dedicated TLS 1.2+ context with the packaged certifi bundle
and ignores ambient proxy, CA-bundle, TLS-key-log, and netrc settings. This
matters because the CLI loads project `.env` files: repository configuration
must not redirect, intercept, or record the ambient bearer token, even through
a loopback listener or a repository-provided TLS root. Local integration tests
replace the endpoint function explicitly and never widen the installed CLI.

The signed Onionwright wheel is installed by isolated Python/pip from its local
path with `--no-index --no-deps` and a cleaned environment. ConnectOnion itself
supplies Onionwright's runtime dependencies (`Playwright`, `PyNaCl`, and `zstandard`) through
its locked package dependency set, then validates the installed version,
preview channel, imports, and paid public surface in an isolated interpreter.

The 1.8.0a5 product decision makes WTFbrowser the default for `co browser`, its
daemon, `BrowserAutomation`, and `AsyncBrowserCore`. `chrome` is the only
canonical non-billing compatibility mode and must be selected explicitly or
saved once with `co browser config set engine chrome`. Every Chrome use warns
about bot detection and account risk. Preflight, balance, download, or launch
failure never changes the requested engine. Host-private Remote Browser always
forces `wtf`. Legacy `auto/onion/system` spellings remain migration aliases.

The #1325 boundary decision does not claim that Playwright's
`service_workers="block"` request blocks Service Workers: real Chrome shows it
does not prevent registration or control. The option remains best-effort
request-visibility hardening; the authenticated loopback egress gateway and
native preflight are the security boundary for private Remote Browser traffic.

| Chromium | `151.0.7922.222` | signed preview catalogue, artifact checksum and provenance |
| oo-api | final dev5 catalogue commit pending | exact preview v2 manifest containing the frozen dev5 digest, minimal route surface, preview bucket, HTTPS, production-host guard |

The dev5 candidate object key is
`onionwright/0.0.13.dev5/onionwright-0.0.13.dev5-py3-none-any.whl`. Its checksum
must be frozen by the reproducible release evidence and immutable upload before
hosted acceptance. Version equality alone cannot distinguish two local builds
with the same dev5 label, so hosted release requires a single generation-zero
dev5 wheel and a catalogue digest for those immutable bytes. The previously
published dev2 wheel SHA-256
`af2a4a617f85b58d5058e7b5e7cf11cd8175ba4f69b0f6fcd1cdfc33cc5bf729`
is historical preview evidence only and must never satisfy the dev5 pin.
The Chromium 151.0.7922.222 digest must be frozen from the immutable preview
object before hosted acceptance.
These values are evidence, not mutable discovery rules: the signed preview
catalogue remains authoritative at runtime.

## Execution stages

1. **Repository isolation**
   - Keep the superseded stacked source as immutable historical evidence.
   - Implement the 1.8 browser preview changes in a dedicated worktree from
     current `main`.
   - Record exact source commits and artifact hashes.

2. **Offline consumer contract**
   - Pin ConnectOnion to exact Onionwright preview version and channel.
   - Reject production/staging/empty signed channels before download or pip.
   - Prove omission selects WTFbrowser and every failed paid preflight fails
     without launching Chrome.
   - Prove explicit Chrome never invokes the paid-token loader or bills, always
     prints the detection/account-risk warning, and can be persisted once.
   - Prove project endpoint/proxy/CA/netrc/Python/pip settings cannot influence
     authenticated preview traffic, signed-wheel installation, or validation.

3. **Isolated control plane**
   - Deploy only auth, licence/PAYG, artifact, and health routes on the preview
     hostname.
   - Use the preview artifact bucket and preview catalogue exclusively.
   - Reuse the production billing identity only with explicit authorization;
     do not clone or print the production environment.
   - Terminate or stop idle preview compute when the gate is paused.

4. **Local exact-artifact acceptance**
   - Build `connectonion-1.8.0a5` once from the reviewed source tree.
   - Install it with Onionwright 0.0.13.dev5 in a fresh temporary environment.
   - Run bootstrap, engine selection, async launch, renewal, close, and release
     against an isolated local preview service.

5. **Hosted preview acceptance**
   - Authenticate without printing credentials.
   - Fetch and verify a signed `channel=preview` manifest.
   - Download the exact Onionwright and Chromium objects and verify checksums.
   - Launch Chromium, exercise HTTPS, WebGL, and a browser download, verify
     server-owned egress, renew once, close, and release.
   - Reconcile exactly one $0.025 interval and verify no session remains active.

6. **Review and publication decision**
   - CI and independent review must be green on exact heads.
   - Update issue #1315 and the replacement PR with public-safe evidence.
   - Keep publication and merge as explicit user decisions. A successful
     preview is evidence for promotion; it is not promotion itself.

## Platform gates

Linux is the public paid-artifact acceptance platform. macOS may use the
approved internal ad-hoc enterprise build for validation. Developer ID signing,
notarization, and public macOS catalogue promotion remain future gates and must
not block internal testing or be represented as complete.
